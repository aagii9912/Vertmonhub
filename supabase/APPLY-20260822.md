### Backfill-ийн хамрах хүрээг УРЬДЧИЛАН харах

Push хийхээс өмнө хэдэн мөр өөрчлөгдөхийг мэдэхийг хүсвэл SQL Editor-т:

```sql
-- Хэдэн гэрээ менежерийн нэр авах вэ
SELECT count(*) AS menejer_bichigdeh
  FROM property_contracts c JOIN leads l ON c.lead_id = l.id
 WHERE NULLIF(TRIM(COALESCE(c.sales_manager,'')),'') IS NULL
   AND NULLIF(TRIM(COALESCE(l.sales_manager_name,'')),'') IS NOT NULL;

-- Хэдэн гэрээ үнэ авах вэ
SELECT count(*) AS une_bichigdeh
  FROM property_contracts c JOIN leads l ON c.lead_id = l.id
 WHERE c.total_price IS NULL AND l.conversion_value IS NOT NULL;
```

Хоёулаа зөвхөн **хоосон** талбарыг дүүргэнэ — гараар оруулсан утгыг хэзээ ч
дарж бичихгүй.

## 3. Push хийсний дараа шалгах

```sql
-- Шинэ хүснэгтүүд
SELECT table_name FROM information_schema.tables
 WHERE table_schema='public' AND table_name IN ('activity_log','work_anomalies');
-- → 2 мөр

-- unique index ЖИРИЙН баганууд дээр байх ёстой (илэрхийлэлт БИШ)
SELECT indexdef FROM pg_indexes WHERE indexname='uq_work_anomalies_daily';
-- → ... USING btree (shop_id, manager_name, kind, detected_on)

-- Триггер менежерийн нэр бичих үү
SELECT prosrc LIKE '%sales_manager%' AS zuv
  FROM pg_proc WHERE proname='create_contract_on_lead_won';
-- → t

-- Роль эрхийн seed
SELECT r.name, count(*) FILTER (WHERE rp.module IN ('marketing','tasks')) AS shine
  FROM roles r LEFT JOIN role_permissions rp ON rp.role_id=r.id
 GROUP BY r.name ORDER BY r.name;
```

## 4. Баталгаажуулалт (аль хэдийн хийгдсэн)

Локал PostgreSQL 16.13 дээр **бүх 125 миграцийг дарааллаар нь** ажиллуулж
(118 амжилттай; унасан 7 нь зөвхөн локалд байхгүй `vector` extension ба
Supabase Storage-ийн улмаас), дараа нь энэ миграцийг хэрэглэв:

- ✅ Цэвэр ажиллав (`EXIT=0`)
- ✅ **Идэмхий** — хоёр дахь удаа ажиллуулахад алдаагүй
- ✅ **Функциональ тест 1:** лид `closed_won` болгоход гэрээ менежерийн
  нэртэй үүсэв, харилцагчийн 250 сая₮ **төсөв үнэ болж бичигдээгүй**
- ✅ **Функциональ тест 2:** бодит `conversion_value` (180 сая₮) зөв бичигдэв
- ✅ **Функциональ тест 3-4:** cron-ийн `ON CONFLICT` ажиллаж, давхардал
  үүсэхгүй (эзэнгүй `manager_name = ''` тохиолдолд ч)
- ✅ **Регрессийн нотолгоо:** хуучин (илэрхийллийн) индекстэй хувилбар дээр
  яг тэр `ON CONFLICT` нь `there is no unique or exclusion constraint
  matching the ON CONFLICT specification` алдаа өгсөн — өөрөөр хэлбэл засварын
  өмнө аномалийн cron **хэзээ ч** мөр хадгалж чадахгүй байсан.
