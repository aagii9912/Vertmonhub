# Meta зарын өдрийн зардлыг файлаар импортлох

`/marketing` дээр **Meta файл импортлох** товч нэмэв. `marketing-roi` бичих эрхтэй
хэрэглэгч API холболт, Meta token, сонгосон API дансгүйгээр CSV/XLSX/TSV файл оруулна.
Энэ хувилбар зөвхөн campaign-ийн өдрийн медиа зардлыг импортлоно. Lead-ийн хүний
мэдээлэл, reach, impressions, clicks, Business Suite-ийн постын тайлан орохгүй.

## Файл бэлтгэх ба ашиглах

1. Ads Manager: Campaigns түвшин, нэг зарын данс, Time → Day задаргаа сонгоно.
2. `Account ID`, `Campaign ID`, `Campaign name`, `Day`, `Amount spent (USD)`
   (эсвэл дансны валют) багануудыг оруулна. `Day`-ийн оронд өдөр бүр ижил утгатай
   `Reporting starts` + `Reporting ends` дэмжинэ. Огноо `YYYY-MM-DD` байна.
3. Нэмэлт Ad/Ad set, нас, хүйс, байршлын задаргааг арилгана. Тухайн дансны бүх
   campaign-ийг экспортлохыг зөвлөнө. 2 MB, 5,000 мөр, 93 хүртэл өдөр, нэг sheet.
4. Файлд данс/валют байхгүй бол цонхонд оруулна. Дансны **бодит цагийн бүс** болон
   байгууллагын тооцооны ханшийг заавал оруулна; MNT бол 1. CSV бутархайн цэг эсвэл
   таслалыг сонгоно. Банкны бодит төлбөрийн ханш гэж үзэхгүй.
5. **Файл шалгах** нь бичилт хийхгүй. Данс, хугацаа, эх валютын нийт, төгрөгийн дүн,
   шинэ/шинэчлэх/хэвээр/API-аас авсан мөрүүд, эхний 20 мөр ба төслийн холбоосыг харуулна.
6. **Баталгаажуулж импортлох** нь нэг transaction-аар хадгална. Хадгалсны дараа
   самбар импортын хугацааг сонгож, тайлан ба төсвийн cache шинэчлэгдэнэ.

Урт Meta ID-г CSV текстээр хэвээр уншина. Excel-д 15-аас олон оронтой ID тоо болж
хадгалагдсан бол боломжит нарийвчлалын алдагдлыг зассан мэт таамаглахгүй, татгалзана.
Нийт хугацааны дүнг өдрүүдэд тараахгүй. Давхардсан campaign/өдөр, холимог данс/валют,
сөрөг/дутуу дүн, буруу огноо, давхардсан багана, хашилтгүй мянгатын таслалаас үүссэн
илүү багана зэрэг нь бүх файлыг зогсооно. Англи болон заасан Монгол багануудыг дэмжинэ;
өөр хэлтэй export бол багануудыг жишигтэй тааруулна. CSV жишгийг цонхноос татна.

## Хадгалалт ба давхардал

- Файл ба API хоёулаа `meta_daily_spend`-ийн `(shop, account, campaign, day)` unique
  түлхүүрийг ашиглана. Мөр бүр `ingestion_source = api | file`, файлын мөр `import_id`-тай.
- Ижил файлын мөрийг дахин оруулахад давхар нэмэхгүй; өөрчлөгдсөн файлын мөр л шинэчлэгдэнэ.
  Шинэ импортын ханш тухайн файлын шинэ/шинэчилсэн мөрүүдэд үйлчилнэ.
- API мөр болон `meta_spend_coverage`-аар баталгаажсан тухайн дансны өдөр файлыг
  алгасуулна. API-аар 0 гэж баталгаажсан өдрийн хуучин зардлыг сэргээхгүй.
  Дараах API синк файлын мөрийг зөвхөн нэг каноник мөр болгон шинэчилж, эх үүсвэрийг API болгоно.
- Файл дутуу байж болох тул **байхгүй мөрийг устгахгүй**, бүрэн өдрийн coverage үүсгэхгүй.
  Файлын хуучин дүнг 0 болгох бол тухайн campaign/өдрийн 0 дүнтэй мөр оруулна.
- Өмнөх гар Meta зардлын давхардлын бодлогыг файлын өдрүүдэд мөн хэрэглэнэ:
  `meta_ads`, `facebook_ads`, `instagram_ads` гар мөрүүд нийтээс хасагдана, устахгүй.
  Preview болон тайланд хасагдсан мөрийн тоо харагдана. Гар бүртгэлд account ID
  байхгүй учир өөр дансны эсвэл хэсэгчилсэн файлын зардлыг оператор тулгах шаардлагатай.
- Нэг хүсэлтийн UUID-гаар дахин оролдвол өмнөх receipt буцна; дараах импорт/API-ийн
  засварыг буцааж дарахгүй. Preview fingerprint өөрчлөгдвөл 409, дахин шалгах шаардлагатай.
- API болон файл нэг shop-ийн advisory lock ашиглана. Preview, хадгалалт, түүх бүгд
  server-authenticated module + shop шалгалттай. Шинэ хүснэгт RLS-тэй, DML/RPC зөвхөн service role.

Төслийн хуваарилалт одоогийн акцын `external_campaign_id` холбоосоор унших үед хийгдэнэ.
Холбоогүй campaign байгууллагын нийтэд орж, дутуу холбоосын тоонд харагдана. Нэг
`loadMarketingSpend`-ээс маркетинг, төсөв, Excel болон AI тайлан уншина. Импортын
сүүлийн 5 receipt файлын цонхонд харагдана; бүх receipt DB-д хадгалагдана.

## Суулгалт

`20260928153000_meta_spend_file_import.sql` нь өмнөх маркетингийн болон Meta daily
spend migration-ууд дээр нэмэгдэнэ. Файл импортлохын өмнө энэ additive migration-ийг
суулгана. Migration хүлээгдэж байх үед хуучин API зардлын тайлан хэвийн ажиллана:
зөвхөн `ingestion_source` багана байхгүй алдаанд хуучин багануудаар дахин уншина;
эрхийн болон бусад DB алдааг нуухгүй. Файл импортын API энэ үед 503 буцаана. Хуучин API function-ийн signature/эрх хэвээр; зөвхөн API
шинэчилсэн мөрийн provenance-ийг тэмдэглэнэ. Migration version-ийг schema_migrations-д
бүртгэнэ. Production DB migration энэ ажлаар хийгдээгүй. Нийтлэг schema-д
өөр migration-тай дугаар давхцахаас сэргийлж хувилбарыг `20260928153000` болгосон.

## Локал баталгаажуулалт

```sh
npx vitest run src/lib/marketing/__tests__
node scripts/test-meta-spend-import.mjs
node scripts/test-meta-spend.mjs
E2E_BROWSER_CHANNEL=chrome npx playwright test --project=marketing
npm run typecheck
```

DB скриптүүд disposable PGlite хэрэглэнэ. Browser нь production credential ашигладаггүй
тусгаарласан auth fixture + mock business API-тай: desktop/mobile preview, failed save,
retry UUID, тайлан/Excel, stale preview, unchanged file, read-only эрхийг шалгана.
Жинхэнэ Meta экспортын жишээ файл болон authenticated production импорт хараахан туршаагүй.

Локал үр дүн: маркетингийн Vitest **70/70**, browser **4/4**, хоёр PGlite SQL скрипт,
TypeScript, өөрчилсөн файлуудын ESLint болон production build тэнцсэн. Desktop/mobile
зураг нягтлаж, mobile dialog-ийн дотоод overflow-ийг зассан. Тестийн өгөгдөлтэй зургууд:
`output/meta-spend-import/desktop-preview.png`, `output/meta-spend-import/mobile-preview.png`.
