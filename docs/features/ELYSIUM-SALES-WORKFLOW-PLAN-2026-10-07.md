# Elysium: уулзалт, үнийн санал, сарын төлөвлөгөө ба гүйцэтгэл

Төлөв: **локал хэрэгжилт, шалгалт хийгдсэн; production migration орсон, deployment хүлээгдэж буй**. Шинэчилсэн: 2026-10-08, Улаанбаатар.

Энэ баримт нь хэрэглэгчийн чат, зургаан зураг, одоогийн код, authenticated live UI,
production DB-ийн зөвхөн унших шалгалтыг нэгтгэсэн. Хэрэглэгчийн «хийж эхэл»
заавраар код, UI, additive migration-уудыг локалд хэрэгжүүлсэн. «Migration
ажиллуулаад gitpush main» заавраар гурван migration-ийг production-д оруулсан.
Бизнесийн өгөгдөл, үнийн тохиргоонд бичээгүй; deployment хүлээгдэж байна.

## Өгөгдлийн зөрүү ба батлах дүрэм

1. Зурагт B1-ийн 50%-ийн үнэ E1/E6, E5 мөрүүдэд хоосон; E3-д байна.
   Бодит нөөцөд **51.72 м² = E6**, **80.32 м² = E5** байна. Энэ нь чатын
   тайлбарыг загвартай холбож өгч байгаа ч хоосон нүдний бизнесийн утгыг
   батлах шаардлага хэвээр. Бүх «80 м²» байранд нэг хасалт хэрэглэхгүй.
2. Талбай нь загвар, давхар, тоотоор өөр байна. B1 E3-ийн нөөцөд 80.00,
   80.53, 80.91, 81.46, 84.66, 85.19 м² байна. B2-ийн зураг ба нөөцийн
   талбай мөн зөрнө: зурагт A = 59.05 м², нөөцөд A = 57.23/57.87/58.00 м².
   Тооцоонд ашиглах талбайн эх сурвалжийг батална; нөөцийг зургаар автоматаар
   засахгүй, ойролцоо м²-ээр дүрэм тааруулахгүй.
3. B1-ийн зураг **2026.05.11–2026.08.31** хүртэл хүчинтэй гэж байна.
   Одоогийн үнийг шинэчилсэн эх сурвалжаар баталж байж идэвхжүүлнэ.
4. 10–30%, 10–50% нь яг хэдийг эхэлж төлөх, хэдийг хэзээ төлөх нөхцөл
   болохыг тогтооно. Зөвхөн шошгоос урьдчилгаа зохиож бодохгүй.
5. «Мөнгөн урсгал» нь орсон төлбөр үү, орлогоос зарлага хассан цэвэр урсгал
   уу гэдгийг батална. Борлуулалтын энэ хэрэглээнд санал болгох нэр нь
   **«Мөнгөн орлого»**; net cashflow-той хольж болохгүй.

Эдгээр нь үнийг идэвхжүүлэхэд хэрэгтэй өгөгдлийн шийдвэрүүд. Байрны зөв
сонголт, хадгалалт, сарын дөрвөн талбарын суурь ажлыг тусад нь хэрэгжүүлж болно.

## 1. Байр сонголт, уулзалтын хадгалалт, засвар

Бодит нөөцийн block/model/area/floor/code-ийг дахин гараар үүсгэхгүй.
Уулзалтад сонирхож буй хувилбаруудын structured жагсаалт нэмнэ. Нэг хувилбар
нь блок, загвар/талбай, сонгосон давхар эсвэл давхарын бүлэг, optional тоот,
optional төлбөрийн нөхцөлтэй байна. Харилцагч хэд хэдэн хувилбар сонирхож
болох тул нэг тодорхой тоот заавал сонгох шаардлага тавихгүй. Тодорхой тоот
сонгосон бол ID, shop/project болон тэр тоотын загвар/талбайг сервер батална.
Тоотгүй хувилбарын block/model/floor/area хослол ч тухайн төслийн баталсан
эх сурвалжид байгаа эсэхийг сервер шалгана. Нэг бүлэгт олон талбай байвал
тодорхой талбай сонгогдтол нийт үнийг бодохгүй.

UI нь нэг хувилбар дотор зөрчилгүй сонголт өгч, «Өөр хувилбар нэмэх» боломжтой
байна. Блок/загвар солиход хуучин нөхцөл, хуучин тооцоог цэвэрлэнэ. Хоосон
үр дүн, ачаалалт, хүсэлтийн алдааг ялгаж харуулна. `agent_notes`-ийг
**«Сэжим / тэмдэглэл»**, placeholder-ийг «Ойрхон амьдардаг…» болгож ашиглана.

Одоогийн units endpoint `property_units_with_buyer.*` уншдаг. Үүнийг уулзалт
бүртгэх эрхтэй бүх хүнд шууд нээхгүй. `viewings`-ийн зөвшөөрөл, shop/project
scope-той minimal selector API гаргаж, зөвхөн байрны сонголтод хэрэгтэй
атрибутыг буцаана; худалдан авагчийн мэдээлэл буцаахгүй.
Санал болгох endpoint нь `GET /api/dashboard/viewings/options`; одоогийн
`properties/search` нь хуучин listing хэрэглэгчдэд хэвээр ажиллана.

`property_id`-тай хуучин уулзалтуудыг үргэлжлүүлэн уншина. Шинэ structured
сонголтуудыг `ViewingService`-ийн create/update validation, route-ууд,
scoped create/update RPC болон types-д хамт нэмнэ. Болсон уулзалтад «Засах»
үйлдэл нэмж, manager өөрийн scope доторх уулзалтыг л засна.

## 2. Баталсан үнийн матриц, нэг тооцоолол

Төслийн үнийн тохиргоонд version, эх сурвалж, хүчинтэй хугацаа болон
block/model/floor-range/condition/sqm-price/advance-rule бүхий дүрмүүд хадгална.
Per-shop хувилбартай нэг тохиргооны хүснэгт, strict schema хангалттай;
ERP snapshot болон `property_units`-ийг үнийн хуудсаар дахин үнэжүүлэхгүй.
Баталсан мөрүүдийг preview-ээр шалгаад идэвхжүүлэх энгийн UI ашиглана.
Ерөнхий PDF/OCR импортын платформ байгуулах шаардлагагүй.
Тохиргооны UI-г «Удирдлага → Төслүүд → Үнийн нөхцөл»-д байрлуулж,
super_admin ба тухайн төслийн хандалтаар хамгаална. Шинэ shared файлыг
`src/lib/sales/pricing.ts`, тохиргооны API-г `/api/admin/pricing`, зөвхөн
тооцооны endpoint-ийг `POST /api/dashboard/viewings/quote` гэж төлөвлөнө.

Shared pricing helper нь яг нэг хүчинтэй дүрэм таарсан үед тооцно. Дүрэмгүй,
олон дүрэмтэй, хүчингүй хугацаатай, боломжгүй нөхцөлтэй үед ойлгомжтой тайлбар
харуулна. Талбайн precision, бүхэл төгрөгийн rounding нэг дүрэмтэй байна.
DB-ийн floor нь «02» зэрэг string тул давхарын заагийг strict normalize хийнэ.
`updated_sale_area = 0`-г бодит 0 м² гэж сохроор сонгохгүй.

Формын доор м² үнэ, нийт үнэ, баталсан нөхцөлөөр урьдчилгаа, үлдэгдэл харуулна.
Хадгалах үед сервер дахин тооцож, client-ийн нийт үнийг итгэж авахгүй.
Тухайн үеийн version/source/area/condition/price/advance snapshot хадгална;
үнийн тохиргоо дараа өөрчлөгдөхөд хуучин уулзалтын санал өөрчлөгдөхгүй.

Одоогийн quote түүхийг ашиглах бол `quotes.ts`, `activities.ts`,
`record_scoped_sales_lead_contact` RPC-ийн metadata allow-list болон AI schema-г
хамт өргөтгөнө. Preview хийх нь quote contact үүсгэхгүй. «Санал өгсөн» гэж
бүртгэх үйлдэл л quote түүх үүсгэнэ; retry-д давхардахгүй байна. Quote нь
гэрээ эсвэл орлого болохгүй, одоогийн money confirmation-ийг тойрохгүй.

## 3. Сарын төлөвлөгөө ба гараар оруулах гүйцэтгэл

Одоо байгаа `team_sales_targets`-ийн shop/year/month мөрийг өргөтгөнө.
`target_amount` нь гэрээний төлөвлөгөө хэвээр; nullable
`cashflow_target_amount`, `manual_contract_actual_amount`,
`manual_cashflow_actual_amount`, actor metadata нэмнэ. Хуучин зорилтот
дүнг migration хэвээр хадгална. Хоосон шинэ нүд unknown; explicit 0 нь 0.

`src/lib/sales/targets.ts`-д сарын дөрвөн утгын shared read/write helper нэмнэ.
Хуучин `getTeamTargets`-ийн хэрэглэгчид contract plan-аа үргэлжлүүлэн авна.
Write нь strict year/month/nonnegative finite amount validation, audit,
өөрчлөгдсөн талбаруудын patch болон stale update detection-той байна. UI/AI
нэг сарын нэг үзүүлэлт засахдаа бусад утгыг арчихгүй.

Одоогийн админы хуудсанд бүтэн өргөний хүснэгт байрлуулна. Менежерийн roster-ийг
доор нь шилжүүлж, жилийн/төслийн сонголтыг ашиглана.

|---|---:|---:|---:|---:|
| 1–12 | Гараар | Гараар | Гараар | Гараар |
