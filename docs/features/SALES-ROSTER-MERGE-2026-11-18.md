# Менежерийн давхар бүртгэл: «Акаунт холбох» ба «Нэгтгэх» (2026-11-18)

## Юу болсон бэ

Mandala Garden-ий борлуулалтын багийг 2026-11-18-нд нэмэхэд ижил хүн бүртгэлд хоёр нэрээр гарсан:

| Гэрээний нэр (июнийн импорт) | Акаунтын нэр (шинэ мөр) |
|---|---|
| Номин.Одончимэг (51 гэрээ) | Nomin |
| Бархүү.Санждорж (282 гэрээ) | Barkhuu |
| Хишигдэлгэр.Баатархүү (239 гэрээ) | Khishegdelger |

Шалтгаан: менежерийн бүртгэлийн нэр нь түлхүүр (лид, уулзалт, гэрээ, өдрийн тайлан…). Акаунт холбох хоёр зам
(Хэрэглэгчид → Төслүүд, «Борлуулалтын төлөвлөгөө»-ний «+ ажилтан» товч) акаунтгүй ажилтанд профайлын нэрээр (латин)
ШИНЭ мөр үүсгэдэг. Систем нэр тааруулж хэзээ ч холбодоггүй (эзэмшигчийн дүрэм — нэрээ өөрчилж бусдын лидийг авах
эрсдэлтэй), бас бүртгэлтэй мөрөнд акаунт холбох, хоёр мөрийг нэгтгэх хэрэгсэл байгаагүй. Нэр солих (`rename_sales_manager`)
шинэ нэр бүртгэлд байвал татгалздаг.

## Шийдэл

- **Акаунт холбох** (`/admin/sales-targets`, акаунтгүй мөр бүрт): төслийн гишүүдээс бүртгэлийн аль ч мөрөнд холбогдоогүй
  акаунтыг сонгоно → «Менежерийн бүртгэл хадгалах» (одоогийн roster PUT, нэг акаунт нэг мөр). Ижил нэртэй ажилтныг
  (хоёр «Nomin») имэйлээр ялгана.
- **Нэгтгэх** (мөр бүрт): энэ мөр (source) → сонгосон мөр (target). `merge_sales_managers` RPC (migration
  `20261118120000`, зөвхөн service_role, super_admin + төслийн хандалтыг дахин шалгана):
  - source нэрийн лид, уулзалт, гэрээ, харилцагч, санал гомдол, өдрийн тайлангийн нүд, тайлангийн загварын багана, байр,
    хуучин төлөвлөгөө, KPI сар target руу; төслийн харьяаллыг нэгтгэнэ; ажлын төлөвлөгөөний хариуцагч (id) target болно;
  - target акаунтгүй бол source-ийн акаунтыг авна; аль нэг нь идэвхтэй бол идэвхтэй; source мөр хасагдана;
  - нэр солихын тэмдгийг (`vertmonhub.manager_rename`) ашиглана — source мөрийг эхлээд хасдаг тул лидийн хамгаалалт,
    хариуцуулалтын ба байрны тамга үүнийг нэр солих гэж таньна (шинэ хариуцуулалт зохиохгүй);
  - өөр өөр акаунттай, эсвэл нэг өдрийн нэг мөрөнд / нэг KPI сард хоёулаа утгатай бол юу ч бичихгүй (огноог нэрлэнэ);
  - «Хэн оруулсан» тамга, өөрчлөлтийн түүх хуучин нэрээрээ; `admin_audit_log` `sales.manager.merge` (хүснэгт бүрийн тоо).
