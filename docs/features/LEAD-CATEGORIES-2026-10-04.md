# Лидийн ангилал

Огноо: 2026-10-04 (Улаанбаатар). Эх сурвалж: 2026-10-04-ний уулзалтын даалгавар №4 «Лидийн ангилал».

Төлөв: хэрэгжсэн (салбар `lane/lead-categories`, wave 2). Migration `supabase/migrations/20261004161000_lead_categories.sql` бичигдсэн, production-д **хараахан ажиллуулаагүй**. Анхдагч ангилал seed хийгээгүй (өгөгдлийн өөрчлөлт хийгээгүй). Production-д deploy хийгдээгүй.

## Дүрэм

- Ангилал нь төсөл (= shop) бүрийн тохиргоо: `lead_categories` хүснэгт (нэр ≤ 60, тайлбар ≤ 300, өнгө `neutral|info|success|pending`, эрэмбэ 0–1000, идэвхтэй/архив). Нэг төсөлд хамгийн ихдээ **30** ангилал (архивласан нь орно) — DB trigger advisory lock-той шалгана (шинэ мөр болон `shop_id`-г өөрчилж өөр төсөл рүү шилжүүлсэн мөрөнд), service мөн адил.
- Нэр том/жижиг үсэг, давхар зай ялгахгүй давтагдахгүй: unique `(shop_id, lead_category_name_key(name))`. Кирилл (Ө, Ү орно) үсгийг `translate()`-аар хувиргадаг тул өгөгдлийн сангийн locale-оос хамаарахгүй. «Ангилалгүй», «none» нэрийг ангилалд ашиглахгүй.
- Лид нэг ангилалтай эсвэл ангилалгүй: `leads.category_id` (NULL = «Ангилалгүй»). Composite FK `(shop_id, category_id) → lead_categories(shop_id, id)` нь лидийг өөр төслийн ангилалд холбохыг DB түвшинд хориглоно (AI, импорт, ирээдүйн зам ч давахгүй).
- Ашиглагдсан ангиллыг (устгасан лидэд ч) устгахгүй — FK `NO ACTION`, API `409` «Архивлана уу» (мессежид лидийн тоо бичихгүй: хувийн хүрээтэй хэрэглэгчид байгууллагын тоо ил гарахгүй). Архивласан ангилал сонгогчид шинээр гарахгүй, өмнө оноосон лидэд «(архив)» тэмдэгтэй харагдана, шүүлтүүр/тайлан/экспортод орно. Лидийн одоогийн архивласан ангиллыг хэвээр үлдээж болно, шинээр оноохгүй.
- Шошго, өнгө, «Ангилалгүй», санал болгох жагсаалт нь `src/lib/leads/labels.ts`-ийн тусдаа блокт (`LEAD_CATEGORY_TONES`, `UNCATEGORIZED_LABEL`, `DEFAULT_LEAD_CATEGORIES`, `leadCategoryLabel`, `categoryNameKey` …). Ангиллын нэр өөрөө DB өгөгдөл.
- Бизнесийн дүрэм нэг газар: `src/lib/services/LeadCategoryService.ts` (жагсаалт, `resolveLeadCategory`, нэмэх/засах/устгах, санал болгох ангилал, тоо, түүхийн бичлэг). `LeadService.resolveStaffLead` ангиллыг шалгадаг тул dashboard POST ба AI `create_lead` нэг дүрэмтэй.
- Ангилал заавал биш. Гадны intake суваг (нийтийн форм, Elysium, Facebook Lead Ads, импорт) ангилалгүй (NULL) бичнэ — менежер/админ дараа нь ангилна.

## Эрх

| Үйлдэл | Эрх |
|---|---|
| Ангиллын жагсаалт унших (`GET /api/dashboard/lead-categories`) | `leads`, `reports-leads` эсвэл `settings` (аль нэг) |
| Ангилал бүрийн лидийн тоо + `referenced` (устгасан лидэд ч холбогдсон, устгах боломжгүй) (`?counts=1`) | `settings` + төслийн хүрээгээр хязгаарлагдаагүй хэрэглэгч (хувийн хүрээтэй менежерт байгууллагын тоо ил гарахгүй) |
| Нэмэх, засах, архивлах, санал болгох ангилал нэмэх (`POST`, `PATCH /[id]`) | `settings` бичих (`withRoute access: 'write'`) |
| Эрэмбэлэх (`PATCH /api/dashboard/lead-categories` `{ order: uuid[] }` — төслийн бүх ангиллын шинэ дараалал, нэг хүсэлт, нэг audit; жагсаалт өөрчлөгдсөн бол `409`) | `settings` бичих |
| Ашиглагдаагүй ангилал устгах (`DELETE`) | `settings` устгах |
| Лидэд ангилал тавих (`PATCH /api/dashboard/leads/[id]` `category_id`, түргэн бүртгэл, AI) | `leads` бичих. Хувийн хүрээтэй менежер зөвхөн өөрийн лид дээр (`applyLeadScope`) |

Ангиллын хүснэгтэд браузер шууд хандахгүй (RLS + `REVOKE … FROM PUBLIC, anon, authenticated`); бичилт зөвхөн service_role. Тохиргооны өөрчлөлт `data_audit_log`-д (`entity: 'lead_category'`, best-effort), лидийн ангиллын өөрчлөлт лидийн түүхэнд `system` бичлэг: «Ангилал: A → B» (`meta: { field: 'category', from, to, from_name, to_name }`).

## Хэрэглэгчийн интерфейс

- **Тохиргоо → «Лидийн ангилал»** (`/dashboard/settings#lead-categories`, `LeadCategoriesSettings`): жагсаалт (өнгөт цэг, тайлбар, лидийн тоо), нэмэх форм (нэр, тайлбар, өнгө), засах, дээш/доош (бүх дараалал нэг хүсэлтээр, жагсаалтад шууд тусна; алдаа гарвал буцна), идэвхтэй/архив switch, ашиглагдаагүйг устгах (зөвхөн устгасан лидэд холбогдсон ангиллын устгах товч идэвхгүй, «Устгасан лидэд ашиглагдсан — архивлана уу»). Хоосон төсөлд «Санал болгох ангиллууд нэмэх» — Орон сууц худалдан авагч, Хөрөнгө оруулагч, Оффис / арилжааны талбай, Түрээслэгч, Бартер, Дилер / Агент (байгаа нэрийг алгасна, дахин дарахад юу ч нэмэгдэхгүй). ⌘K-д «Лидийн ангилал», админы тохиргооны самбарт холбоос.
- **Лидийн жагсаалт**: «Ангилал» шүүлтүүр (`category=<id>|none`, архивласан «(архив)»-тай, «Цэвэрлэх» болон ажлын жагсаалт сонгоход цэвэрлэгдэнэ), хүснэгтийн «Ангилал» багана дээрх inline сонгогч, бөөнөөр «Ангилал:» тавих, гар утасны мөрийн дэд мөрөнд ангиллын нэр. Төсөлд ангилал алга бол багана, шүүлтүүр харагдахгүй.
- **Лидийн панел**: «Эх үүсвэр»-ийн доор «Ангилал» мөр (бичих эрхтэй бол сонгогч).
- **Түргэн бүртгэл**: заавал биш «Ангилал» (≤ 8 бол чип, олон бол select); зөвхөн идэвхтэй ангилал; payload-д `category_id` (offline outbox-д ч). Outbox хожуу илгээхэд ангилал архивлагдсан бол сервер `400` тодорхой мессеж буцаана.
- **Pipeline**: карт дээр ангиллын тэмдэг, «Ангилал» шүүлтүүр (ачаалсан ≤ 1000 лид дээр клиент талд; самбар, таамаг хоёуланд үйлчилнэ).
- Ангиллын тэмдэг: саарал pill дээр `--status-*` өнгөт цэг — статусын pill-тэй андуурахгүй, алдааны (danger) өнгө ашиглахгүй.

## Тайлан, экспорт

- Үйл ажиллагааны тайлан (`/dashboard/reports/operations`, AI `get_operations_report`): «Ангиллаар» — хугацаанд шинээр орсон лидийг тохиргооны эрэмбээр, дараа нь «Ангилалгүй» (тоо 0 мөрийг харуулахгүй, нийлбэр нь шинэ лидийн тоо). Текст хувилбарт «Ангиллаар: …» мөр. Ангилалгүй төсөлд задаргаа хоосон.
- Лидийн тайлан (`/dashboard/reports/leads`): «Ангиллаар» карт — лид, амжилттай, хөрвүүлэлт. Хуудасны бусад хэсгийн адил ≤ 1000 лид дээр тооцно.
- Excel лидийн экспорт: «Эх сурвалж»-ийн дараа «Ангилал» багана (архивласан «(архив)», NULL «Ангилалгүй»). Ангиллыг уншиж чадаагүй бол экспорт алдаа буцаана (хоосон багана гаргахгүй).

## AI туслах

- `list_lead_categories` (унших; `leads` эсвэл `reports-leads`): нэр, тайлбар, архивласан эсэх.
- `set_lead_category` (бичих, `leads`, төслийн хүрээтэй, AUTO «Ангилал тавих» — буцаах боломжтой, лидийн түүхэнд бичигдэнэ; мөнгө/устгах/гадагш мессеж биш): ангиллын яг нэрээр эсвэл «Ангилалгүй»-гээр цэвэрлэнэ.
- `create_lead`, `list_leads` нь `category` (нэр) хүлээн авна; `list_leads`, `get_lead_details` ангиллын нэрийг буцаана. Нэр таарахгүй бол таамаглахгүй — боломжтой нэрсийг жагсаасан алдаа буцаана. Prompt-д «ангилал бүү зохио» дүрэм нэмэгдсэн.
- `list_leads`-ийн `source` enum-ийг хуучин 6 утгаас `SOURCES` (нэг толь) болгосон.
- Агентууд: `list_lead_categories` — data-analyst, crm-specialist, marketing-specialist (`list_leads`-ийн ангиллын нэрийг эндээс авна); `set_lead_category` — crm-specialist.

## Production-д нэвтрүүлэх алхам

1. **Код deploy хийхээс өмнө** migration-ийг node + `pg`-ээр нэг гүйлгээнд ажиллуулж `supabase_migrations.schema_migrations`-д `20261004161000` бүртгэнэ. Эсрэг дарааллаар бол үндсэн урсгал ажиллана — лидийн `PATCH` нь `category_id`-г зөвхөн ангилал өөрчлөхөд уншиж бичдэг, dashboard `POST` ба AI `create_lead` ангилалгүй лидэд баганыг бичдэггүй — гэхдээ ангиллын бүх боломж (Тохиргоо, шүүлтүүр, ангилал тавих), үйл ажиллагааны тайлан (`category_id`, `lead_categories` уншдаг), AI `list_leads` migration-гүй бол алдаа буцаана. `leads`-д composite FK нэмэхэд богино `SHARE ROW EXCLUSIVE` түгжээ авна; бүх утга NULL тул шалгалт хурдан — ачаалал багатай үед ажиллуулна.
2. Шалгах: `SELECT count(*) FROM lead_categories;` (0), `\d leads` (`category_id`, `leads_category_same_shop_fkey`), `node scripts/rls-audit.mjs`.
3. Төсөл бүрт админ Тохиргоо → «Лидийн ангилал» → «Санал болгох ангиллууд нэмэх» дарна (эсвэл өөрийн жагсаалтаа үүсгэнэ). Бүх төсөлд SQL-ээр урьдчилан бөглөх бол (`INSERT … SELECT FROM shops … ON CONFLICT DO NOTHING`) эзэмшигчийн тусгай зөвшөөрөлтэй, тусдаа statement байна.

## Мэдэгдэж буй хязгаар

- Лидийг өөр shop руу зөөх (төсөл хуваах `scripts/lib/project-shop-split.mjs` дахин ажиллуулах г.м.) үед ангилалтай лид FK-аар саатна — эхлээд ангиллыг шинэ shop-д хуулах эсвэл `category_id`-г NULL болгоно. 2026-10-04-ний хуваалт аль хэдийн хийгдсэн, дахин ажиллуулахад no-op.
- Төсөл бүрийн жагсаалт өөр өөр тул төсөл хоорондын харьцуулалт нэрээр тулгана (санал болгох жагсаалт нийтлэг суурь болно).
- Шинэ төсөл (`create_project_shop`) ангилалгүй эхэлнэ — Тохиргооны хоосон төлөв «Санал болгох ангиллууд нэмэх»-ийг санал болгоно.
- Админ импортын «Ангилал» багана, AI-ийн бөөнөөр ангилах (`bulk_update_leads`), кампанит ажлын анхдагч ангилал энэ хувилбарт ороогүй.
- «Оффис / арилжааны талбай» нь «Сонирхол»-ын оффис, «Бартер» нь `financing_intent`/нэгжийн бартер төлөвтэй давхцаж болно — тайлбарт «харилцагчийн төрөл/зорилго» гэж тодорхой бичсэн.
