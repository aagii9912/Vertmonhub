# Гэрээний жагсаалт ERP-ийн «HUB» загвараар: импорт, төлөвлөгөөний биелэлт

Огноо: 2026-10-22 (Улаанбаатар). Салбар: `feat/elysium-contracts-hub`.

**Төлөв:**
- Код, тест салбар дээр бэлэн; main-д нэгтгээгүй, deploy хийгээгүй.
- Migration `20261022140000_contract_list_import.sql` production-д **ороогүй**. Deploy хийхээс өмнө заавал оруулна.
- Production-д HUB импорт **хийгээгүй**. Доорх тоо нь бодит файл болон зөвхөн уншиж авсан хуулбараар загварчилсан урьдчилсан тооцоо.
- Шийдвэр 6 (багийн гүйцэтгэлийг төслийн түвшинд тоолох) эзэмшигчийн баталгааг хүлээж байна.

## Юу өөрчлөгдсөн

- **Гэрээний жагсаалт** (`/dashboard/contracts`):
  - Анхдагч харагдац нь ERP-ийн HUB файлын 16 багана, дараалал нь ч ижил. Хоёр харагдацын хооронд шилжинэ: «HUB загвар» ба «Төлбөр, менежер».
  - Карт: «Нийт гэрээ», «Нийт дүн» (цуцалсныг хассан), «Төлөх урьдчилгаа» (орсон мөнгө биш), «Төлбөр хоцролт» (файлын огноотой).
  - Шүүлт: Төрөл, Блок, Төлөв, Захиалгын нөхцөл, Менежер, «Хоцролттой», «Сүүлийн файлд байхгүй», огноо.
  - Хүснэгтийн хөлд шүүсэн гэрээний нийлбэр гарна.
  - «Excel татах» хоёр сонголттой: «HUB загвар (16 багана)» (`type=contracts_hub`) ба «Дэлгэрэнгүй (төлбөр, менежер, шилжүүлэг)».
- **Гэрээний дэлгэрэнгүй:**
  - Шинэ талбар: «Захиалга өгсөн огноо», «Захиалгын нөхцөл», «Төлбөр хоцролт» (файлын огноогоор), Нэр/Овог.
  - Огноогүй гэрээнд «Огноо оруулах» товч гарна. PATCH `order_date` нь зөвхөн огноо хоосон үед ажиллана (бөглөгдсөн бол 409). Гэрээний огноо хоосон бол түүнийг ч бөглөнө.
- **HUB импорт:** «Гэрээ» → «Excel импорт» (`/dashboard/contracts/import`). Доорх дүрмийг үзнэ үү.
- **Төлөвлөгөөний биелэлт** (`/dashboard/reports/plan`):
  - Сар бүрийн гэрээний тоо, дүн, мөнгөн урсгалыг төлөвлөгөөтэй харьцуулна. Блокоор харж болно: Нийт · Б1 · Б2 · Зогсоол.
  - Ижил дүрмийг Director, `/admin/sales-targets`-ийн «CRM-ээр тооцсон» багана, үйл ажиллагааны тайлангийн төлөвлөгөөний хувь хэрэглэнэ.
- **Цуцалсан, устгасан гэрээг тооцоонд оруулахгүй:** AI-ийн статистик, гэрээний статистик, KPI-ийн нөөц тоо, долоо хоногийн болон захиралын cron, `property_units_with_buyer`, `import-erp-snapshot` (цуцалсан гэрээ байрыг эзэлсэнд тооцогдохгүй).
- **ERP импортын хуудас:** HUB файлыг snapshot болгож хадгалахгүй. Оронд нь гэрээний импорт руу чиглүүлнэ.

## Файлын формат (16 багана)

`src/lib/contracts/list-format.ts` нь жагсаалт, экспорт, импорт, AI-ийн нэг эх сурвалж.

| Багана | DB | Тэмдэглэл |
|---|---|---|
| Төрөл | `product_type` | Орон сууц / Зогсоол / Агуулах / Үйлчилгээ |
| Блок | `block_name` | |
| Тоот | `legacy_unit_number` ?? `unit_number` (0 биш) ?? кодоос | Экспортод цифр бол тоогоор бичнэ. «084» шиг 0-ээр эхэлсэн бол текстээр үлдэнэ. |
| Давхар | `floor` | DB-д «01», файлд «1». «B1» өөрчлөгдөхгүй. |
| Загвар | `model` | |
| Гэрээлсэн талбай | `contracted_area` | 2 орон |
| Урьдчилгааны нөхцөл | `prepayment_condition` | |
| М.кв үнэ | `price_per_sqm` | Зогсоол/агуулахад хоосон бол экспорт нийт дүнг бичнэ (ERP нэгжийн үнийг энд бичдэг). Импорт зөвхөн талбай × үнэ нь нийт дүнтэй 1%-ийн дотор таарвал хадгална. |
| Нийт дүн | `total_price` | |
| Урьдчилгааны дүн | `prepayment_due` | Нөхцлөөр төлөх ёстой дүн. Орсон мөнгө биш. |
| Төлбөр хоцролт | `overdue_amount` + `overdue_as_of` | Файлын огнооны байдлаар. NULL = мэдэгдэхгүй, 0 = хоцролтгүй. |
| Захиалга өгсөн огноо | `order_date` **ба** `contract_date` | |
| Төлөв | `contract_status` | Гэрээ үүссэн = active, Гэрээ хаасан = closed, Цуцлагдсан = cancelled, Тоот шилжсэн = transferred (импортлохгүй). Апп-ын үг (Идэвхтэй, Хаагдсан…) ч танигдана. |
| Нэр, Овог | `customer_first_name`, `customer_last_name` | Нэр салгаагүй гэрээнд экспорт `customer_name`-ийг «Нэр»-д бичнэ. |
| Захиалгын нөхцөл | `payment_condition` | |

**Нэмэлт багана.** Импорт гурван нэмэлт баганыг таньдаг:
- «Гэрээний дугаар» ба «Борлуулалтын менежер»: гэрээнд хоосон бол л бөглөнө.
- «Нийт төлсөн дүн»: зөвхөн `contract_list_imports.rows`-д хадгална. Гэрээнд хэзээ ч бичихгүй.

Бусад баганыг «Импортлохгүй багана» гэж жагсаана.

**Файл:**
- Зөвшөөрөх төрөл: .xlsx, .csv, .tsv, 4 MB хүртэл. .xls файлд 400 буцаана.
- Баганын нэрийн өмнө, хойно зай байвал асуудалгүй. 16 баганатай эхний sheet-ийг уншина.

**Мөр:**
- Excel-ийн хөвөгч таслалын үлдэгдлийг центээр бөөрөнхийлнө (403415999.9999999 → 403 416 000; −1.49e-8 → 0).
- Сөрөг мөнгөн дүн байвал алдаа.
- Нэг мөр алдаатай бол файл бүхэлдээ орохгүй. Бүх алдааг мөрийн дугаартай нь жагсаана.
- Алгасах мөр: «Тоот шилжсэн», огноогүй мөр (гэрээ хэвээр үлдэнэ), байрны мэдээлэлгүй (нийлбэрийн) мөр.

**Буцаан импорт.** Системийн HUB экспортыг ижил огноогоор буцааж импортлоход өөрчлөлт 0 гарна. Үүнийг `src/app/api/dashboard/export/excel/__tests__/contracts-export.test.ts` шалгадаг.

## Импортын дүрэм ба тулгалт

Код: `src/lib/contracts/list-import.ts` (цэвэр функц), `src/lib/services/ContractListImportService.ts`, `src/app/api/dashboard/contracts/import/route.ts`.

1. **Байр олох.**
   - «Төрөл» нь байрны ангилалтай таарах ёстой. Код нь `Блок-Тоот` эсвэл `Блок-Тоот (…)`.
   - Олон байр таарвал эхлээд давхраар, дараа нь загвараар шүүнэ. Жишээ: «Б1-19 (B1)» / «Б1-19 (01)», «Б1-46 (H-1)» / «(H-2)».
   - Яг нэг байр үлдэх ёстой. Үгүй бол мөрийн алдаа.
2. **Тулгалт** байраар (`product_type|unit_label`) хийгдэнэ:
   - Идэвхтэй/хаасан мөрийг амьд гэрээтэй (идэвхтэй/хаасан/тоот шилжсэн) холбоно. Эхлээд захиалгын огноо яг ижилийг, дараа нь шинэг шинэтэй.
   - Цуцлагдсан мөрийг цуцалсан гэрээтэй огноогоор холбоно.
   - Цуцлагдсан мөртэй ижил огноотой амьд гэрээ байвал тэр гэрээ цуцлагдана («Шалгах»). Байр дахин зарагдсан бол шинэ мөр нь шинэ гэрээ болно.
   - Байранд амьд мөр байхгүй бол үлдсэн цуцлагдсан мөр огноогүй амьд гэрээг цуцална («Шалгах»). Тийм гэрээ олдохгүй бол түүх болгож цуцалсан гэрээ нэмнэ.
   - Нэг байранд хоёр амьд гэрээ хэзээ ч үүсгэхгүй.
3. **Өөрчлөлтийн ангилал:**
   - *Шинэчлэгдэх* (автоматаар):
     - хоосон огноо, нөхцлийг бөглөнө;
     - «Захиалгын нөхцөл»;
     - төлбөр хоцролт: холбогдсон мөр бүрт `overdue_as_of` = файлын огноо болно;
     - Нэр/Овог: хоёулаа хоосон, «Нэр.Овог» = `customer_name`, Hub-д шилжүүлээгүй гэрээнд л бөглөнө;
     - гэрээний дугаар, менежер хоосон бол бөглөнө;
     - Гэрээ үүссэн → Гэрээ хаасан.
   - *Шалгах шаардлагатай*: зөвхөн «Дүн, төлөв өөрчлөгдөх гэрээг шалгасан»-ыг чагталсны дараа хадгалагдана. Үүнд:
     - DB-д утгатай Нийт дүн, М.кв үнэ, урьдчилгааны дүн/нөхцөл, талбай, огноог өөрчлөх;
     - цуцлах;
     - хаасан/цуцалсан гэрээг дахин идэвхжүүлэх.
   - *Батлахыг хаана*:
     - төлсөн дүн бүртгэлтэй гэрээний дүн/нөхцлийг өөрчлөх;
     - төлбөртэй (хуваарь, төлөлттэй) гэрээг цуцлах;
     - байртай холбоогүй гэрээ;
     - нэг байранд хоёр амьд гэрээ.
   - *Мэдээлэл* (батлахыг хаахгүй):
     - Эзэмшигч зөрүүтэй. Импорт нэрийг өөрчлөхгүй. Засахдаа «Гэрээ шилжүүлэх» → «Нэр засах».
     - Hub-д шилжүүлсэн гэрээ (нэр хэвээр).
     - ERP-д «Тоот шилжсэн» гэрээ.
   - Файлд хоосон утга DB-ийн утгыг арилгахгүй. Ганц үл хамаарах зүйл нь төлбөр хоцролт: файлд хоосон бол «мэдэгдэхгүй» (NULL) болно.
4. **Шинэ гэрээ:**
   - Файлын утгууд дээр байрны баганууд нэмэгдэнэ (`contractUnitColumns`, бүтээгдэхүүний импортын дүрэм).
   - `customer_name` = «Нэр.Овог».
   - Тэмдэглэл: «Гэрээний жагсаалт «файл» (огноо)-аас импортолсон.»
   - `paid_amount`, `balance`, `penalty_amount`, `overdue_days` = NULL.
5. **Өөрчлөхгүй, зөвхөн жагсаана:**
   - «Файлд байхгүй»: DB-д байгаа боловч файлд ороогүй гэрээ.
   - «Байрны төлөв зөрүүтэй»: идэвхтэй гэрээтэй боловч байр чөлөөтэй/захиалсан, эсвэл зөвхөн цуцалсан гэрээтэй боловч байр зарагдсан. Импорт байрны төлөвийг өөрчлөхгүй.
   - «Файлын нийлбэр» төлөв бүрээр: мөр, Нийт дүн, Урьдчилгааны дүн, Төлбөр хоцролт. Excel-ийн SUM-тай тулгахад зориулсан.
6. **Огнооны хамгаалалт:**
   - «Файлын огноо» өнөөдрөөс (УБ) хойш байж болохгүй, файлын хамгийн сүүлийн захиалгын огнооноос өмнө ч байж болохгүй.
   - Сүүлийн импортоос хуучин файл оруулахад «Хуучин файлыг мэдсээр оруулж байна» гэж баталгаажуулна.
7. **Батлах:**
   - Сервер төлөвлөгөөг дахин тооцоолж hash-ийг тулгана. Зөрвөл 409 «Өгөгдөл өөрчлөгдсөн, дахин шалгана уу».
   - `import_contract_list` RPC нэг гүйлгээнд ажиллана:
     - эхлээд бүх өөрчлөлтийг урьдчилан харсан утгатай (`expect`) тулгана; нэг нь зөрвөл юу ч бичихгүй, 409 `conflicts` буцаана;
     - дараа нь бичнэ;
     - гэрээ бүрт `data_audit_log`, нийтдээ нэг `admin_audit_log` (`contracts.list_import`), мөн `contract_list_imports`-д нэг мөр (зөвхөн нэмэгдэнэ) бичнэ.
   - Ижил хүсэлтийн ID-гаар давтан илгээвэл хадгалсан хариуг буцаана. Давхар бичихгүй.
   - RPC-ийн зөвшөөрсөн талбарын жагсаалтад `paid_amount`, `balance`, `prepayment_paid*`, `paid_percent`, `customer_name`, байрны төлөв ороогүй.
   - Migration ороогүй бол 503 «Гэрээний импортын шинэ migration ороогүй байна…».
8. **Эрх:**
   - `contracts` болон `erp-imports` модульд бичих эрх хэрэгтэй.
   - Төслийн хүрээгээр хязгаарлагдсан менежерт 403 «Гэрээний импорт удирдлагад зориулагдсан».
   - Shop-д яг нэг төсөл байх ёстой.

## Эзэмшигчийн шийдвэр (2026-10-22)

1. «Захиалга өгсөн огноо» нь `order_date` ба `contract_date` хоёуланг бөглөнө. Mandala-д эдгээр аль хэдийн ижил. ERP-ийн долоо хоногийн тайлан, KPI ч үүнийг борлуулалтын огноо гэж үздэг.
   - Ингэснээр «ERP-ийн гэрээ огноогүй» гэсэн өмнөх дүрэм солигдоно.
   - Огноогүй хэвээр үлдэх нь зөвхөн файлд байхгүй гэрээ.
2. Elysium-ийн гэрээний эзэн нь ERP:
   - Импорт гэрээний талбаруудыг файлтай тулгаж шинэчилнэ.
   - Төлсөн дүн, үлдэгдэл, урьдчилгааны төлөлт, төлсөн хувийг хэзээ ч бичихгүй.
   - Шинэ гэрээнд `paid_amount`, `balance` = NULL (баганын анхдагч утга 0 биш).
3. Эзэмшигчийг импортоор солихгүй. Солих бол «Гэрээ шилжүүлэх» ашиглана; Б2-199-ийн утасны дугаар бичигдсэн нэрийг «Нэр засах»-аар засна. Нэр/Овог зөвхөн хоосон үед бөглөгдөнө (дүрэм: дээрх 3-р хэсэг).
4. Байрны төлөвийг (`property_units`) импорт өөрчлөхгүй (D2 шийдвэр хүлээгдэж байна). Зөрүүг жагсаана.
5. DB-д байгаа боловч файлд байхгүй гэрээ хэвээр үлдэнэ, «Файлд байхгүй» жагсаалтад гарна.
6. **Багийн төлөвлөгөөний гүйцэтгэлийг төслийн түвшинд тоолно**: төслийн бүх амьд, огноотой гэрээ, аль ч менежерийнх. Учир нь `team_sales_targets` 2026-10-04/08-аас хойш төслийн төлөвлөгөө болсон.
   - Хувийн тоо, leaderboard роостероор хэвээр.
   - Энэ нь 2026-07-01-ний «багийн гүйцэтгэл = зөвхөн идэвхтэй менежерүүд» дүрмийг (`20260701140000`) төлөвлөгөөтэй харьцуулах тоонд хүчингүй болгож байна. **Эзэмшигч батлах шаардлагатай.**
7. Орсон мөнгийг HUB файлаас хэзээ ч тооцохгүй (файлд төлсөн багана байхгүй). «Урьдчилгааны дүн» нь төлөх үүрэг. Зөвхөн гэрээний хэсэгт харагдана, мөнгөн урсгалын төлөвлөгөөтэй харьцуулахгүй.

## Төлөвлөгөөний биелэлт ба мөнгөн урсгал

Код: `src/lib/sales/plan-buckets.ts`, `plan-performance.ts` (цэвэр функц), `plan-performance-load.ts`; API `GET /api/dashboard/reports/plan-performance?year=`.

**Эрх:** `reports` модуль (super_admin орж чадна). Төслийн хүрээгээр хязгаарлагдсан менежерт 403.

- **Гүйцэтгэл** (шийдвэр 6):
  - Төслийн бүх амьд гэрээ тооцогдоно.
  - Сарыг `contract_date`-ийн YYYY-MM-ээр тодорхойлно.
  - Цуцлагдсан, устгасан гэрээ орохгүй. Тооцоо одоогийн төлвөөр: дараа нь цуцлагдсан гэрээ захиалсан сарынхаа гүйцэтгэлээс хасагдана.
- **Блок** (`planBucketOf`):
  - Орон сууц + Б1 → b1, Орон сууц + Б2 → b2, Зогсоол (аль ч блок) → parking.
  - Агуулах, Үйлчилгээ, бусад блок нь «Төлөвлөгөөнд хамаарахгүй» тусдаа мөрөнд гарна. Харин сарын төлөвлөгөө блокоор задлаагүй (зөвхөн нийт) бол бусад блокийн орон сууц нийтэд орно.
- **Гар ба системийн дүн** хэзээ ч нэмэгдэхгүй:
  - Блокийн нүдэнд гараар оруулсан тоо байвал түүнийг, үгүй бол системийн тоог авна.
  - Блокоор задалсан үзүүлэлтийн нийт = блокуудын нийлбэр.
  - Задаргаагүй бол гараар оруулсан нийтийг, түүнийг ч оруулаагүй бол системийн блокуудын нийлбэрийг авна.
- **Доод хязгаар «+»:**
  - Огноогүй амьд гэрээтэй блокийн системийн дүн доод хязгаар болно. Тухайн сард гэрээ огт байхгүй бол «—», байвал «N+» (хувь «N%+»).
  - Гараар оруулсан нүд хэзээ ч «+» биш.
  - Төлөвлөгөө эсвэл гүйцэтгэл мэдэгдэхгүй бол хувь null, 0 биш.
- **Хугацаа:**
  - Ирээдүйн сарын гүйцэтгэл null. Энэ сар «явцын» гэж тэмдэглэгдэнэ.
  - Оны дүн хоёр янзаар: «Он эхнээс (1–M сар)» ба «Жилийн төлөвлөгөөнөөс».
- **«Нөхцлөөр төлөх урьдчилгаа»:**
  - Тухайн сард захиалсан амьд гэрээний `prepayment_due`-ийн нийлбэр.
  - Зөвхөн мэдээлэл. Мөнгөн урсгалын төлөвлөгөөтэй харьцуулахгүй.
- **Мөнгөн урсгал** (зөвхөн super_admin эсвэл `finance`; бусдад `cashHidden`):
  - Гараар оруулсан дүнг авна. Үгүй бол бүртгэсэн төлбөрийг: бэлэн, банк, шилжүүлэг, ипотек. Бартер орохгүй.
  - Амьд гэрээ бүрийн төлсөн дүн мэдэгдэж байвал бүтэн дүн. Заримынх NULL бол доод хязгаар. Бүгд NULL бол «—».
  - Урьдчилгааны дүн, хоцролт, «нийт − урьдчилгаа»-г хэзээ ч орсон мөнгө гэж тооцохгүй.
  - Elysium-ийн гэрээний төлсөн дүн одоогоор бүгд NULL тул «—».
- **Төлбөр хоцролт:**
  - Сүүлийн импортын огноотой (`overdue_as_of`) идэвхтэй гэрээний `overdue_amount`-ийн нийлбэр.
  - Өмнөх файлын утгыг «хуучирсан» гэж тусад нь тоолно. Ижил дүрмийг `lib/contracts/summary.ts`, `live.ts` хэрэглэнэ.
- **Хаана хэрэглэгдэх вэ:**
  - Director: сарын гүйцэтгэл, трэнд, он. Leaderboard менежерээр хэвээр.
  - `/admin/sales-targets`-ийн «CRM-ээр тооцсон» багана.
  - Үйл ажиллагааны тайлан: төлөвлөгөөнд хамаарах гэрээний дүнгээр хувь, огноогүй гэрээ байвал «N%+».
  - Лхагвагийн слайд: аль нэг мөрийн төлсөн дүн мэдэгдэхгүй бол «Төлсөн» нийлбэр «—» (заримынх мэдэгдэж байвал «N+»).

## Production-д ажиллуулах

1. Migration оруулна (дээр нь `20261022120000`, `20261022160000` production-д аль хэдийн байгаа):
   ```bash
   node scripts/apply-migrations.mjs 20261022140000 20261022140000          # зөвхөн шалгана
   node scripts/apply-migrations.mjs 20261022140000 20261022140000 --apply  # оруулна
   ```
   IPv6 холболтгүй сүлжээнээс оруулах бол Supabase SQL Editor ашиглана. Дараа нь хувилбарыг `supabase_migrations.schema_migrations`-д бүртгэнэ. `apply-migrations.mjs`-ийн VERIFY шалгана: багана байгаа эсэх, хүснэгтэд RLS асаалттай ба anon/authenticated эрхгүй эсэх, функцийг зөвхөн service_role ажиллуулж чадах эсэх, view байгаа эсэх.
2. Код deploy хийнэ.
3. UI-аас импортлох (super_admin, эсвэл гэрээ + ERP импортын бичих эрхтэй удирдлага):
   1. «Гэрээ» → «Excel импорт».
   2. Файлаа сонгоод «Файлын огноо»-нд ERP-ээс татсан өдрийг оруулна. Төлбөр хоцролт тэр өдрийн байдлаар хадгалагдана.
   3. «Файл шалгах» дарна.
   4. «Шалгах» алхамд хураангуй, «Файлын нийлбэр»-ийг Excel-ийн SUM-тай тулгана.
   5. «Шалгах шаардлагатай» жагсаалтыг харж «Дүн, төлөв өөрчлөгдөх гэрээг шалгасан»-ыг чагтална.
   6. «Батлах» дарж баталгаажуулна.
   7. «Хадгалсан» алхамд тоо болон «Гэрээ харах», «Төлөвлөгөөний биелэлт», «Өөрчлөлтийн түүх» холбоос гарна.
   - Хариу ирээгүй бол «Батлах»-ыг дахин дарж болно. Ижил хүсэлтийн ID тул давхар хадгалагдахгүй.
4. Импортын дараа хийх ажил:
   - «Байрны төлөв зөрүүтэй» байруудыг «Байр»-аас гараар засна.
   - Б2-199-ийн нэрийг «Гэрээ шилжүүлэх» → «Нэр засах»-аар засна.
   - «Файлд байхгүй» огноогүй гэрээг ERP-тэй тулгана.

## Хийгээгүй, дараагийн алхам

- **Байрны төлөвийн синк (D2):** импорт байрны төлөвийг өөрчлөхгүй. Синк хийх эсэхийг эзэмшигч шийднэ.
- **Бодит орсон мөнгө:** ERP-ийн файлд «Нийт төлсөн дүн» багана нэмүүлнэ. Импорт түүнийг `contract_list_imports.rows`-д аль хэдийн хадгалдаг. Хоёр импортын зөрүүгээр мөнгөн урсгал гаргах ажил хийгдээгүй. Гэрээний төлсөн дүнд хэзээ ч бичихгүй.
- **Роостерт суурилсан тоо:** my-stats, KPI, `manager_performance` хувийн тоог роостероор тоолсоор байна. ERP-ийн менежерийн нэр роостертэй таарахгүй бол дутуу гарна.
- **Хязгаарлагдсан менежерийн хүрээ:** гэрээний жагсаалт, экспортод өөрчлөлт ороогүй (main-тай ижил). `contracts` модультай хэрэглэгч төслийн бүх гэрээг харна.
- **Шийдвэр 6:** эзэмшигчийн баталгаа хүлээгдэж байна. Хэрэв роостерын дүрмийг хадгалах бол тоог «Идэвхтэй менежерүүдийн гэрээ» гэж нэрлэж, төслийн төлөвлөгөөтэй хувиар харьцуулахгүй.
