- 2026-10-13-ны байдлаар production-д маркетингийн бүх хүснэгт хоосон байв: сувгийн экспорт, Meta зардал, төсөв, кампанит ажил, хурлын шинэчлэл бүгд 0. Маркетингийн ганц хэрэглэгч сүүлд 2026-07-02-нд нэвтэрсэн.

## Хурлын хуудас

Хуудас хоёр хэсэгтэй, слайд нь хоёр тусдаа файл. Файлыг хөтөч дээр үүсгэдэг (`lib/dashboard/weekly-deck-export.ts`). `pptxgenjs` зөвхөн товч дарахад ачаалагдана, хуудасны эхний bundle-д орохгүй.

- **«Борлуулалтын слайд»** (`reports` эрх): `<Төсөл> - Борлуулалт - Лхагва <огноо>.pptx`.
- **«Маркетингийн слайд»** (`marketing-roi` эрх): `<Төсөл> - Маркетинг - Лхагва <огноо>.pptx`.

Борлуулалтын хэсэг:

- 01 Борлуулалтын тойм, 01·2 Гэрээ, үлдэгдэл, давхрын зураглал.
- **01·3 «Лидийн эх сурвалж, хөрвөлт»** (`marketing-roi` эрхтэй хүнд). Энэ нь өмнө «Маркетингийн үр дүн» хэсэгт байсан лид, шилжилт, гэрээлэлт, сувгийн хүснэгт юм. Лидийн эх сурвалж нь борлуулалтын үзүүлэлт тул энд шилжсэн.
- **01·4 «Борлуулалтын нэмэлт слайд»** (`reports`): өдөрлөгийн зураг, хүлээлцсэн байдал, яригдаж буй гэрээ, энэ сарын ажил.

Маркетингийн хэсэг:

- **02 «Маркетинг — контент төлөвлөгөө ба гүйцэтгэл»**: маркетингийн өөрийн төлөвлөгөө (Контент календарь, `content_calendar`).
  - Тайлант долоо хоногийн төлөвлөсөн, нийтэлсэн (%), хийгдэж буй/бэлэн, хоцорсон контентын тоо, төрлөөр задаргаа. Хажууд нь өмнөх хурлын долоо хоногийнх: «Өмнөх 7 хоног: төлөвлөсөн X / нийтэлсэн Y» (`previousContentText`; хуудас, слайд, текст тайлан).
  - Контентын хүснэгт, төлвийг шууд солих боломжтой.
  - Дараагийн 7 хоногийн төлөвлөгөө, «Контент нэмэх».
- **02·2 «Суваг: Page, Instagram, Ads, CallPro, SMS · төсөв»**: гарчгийн доор нэг мөр «Холболтын төлөв» (доорх «Холболт, эх сурвалж»), Facebook хуудас ба Instagram-ийн долоо хоногийн үзүүлэлт (доорх), сувгийн экспорт/Meta API, маркетингийн жилийн төсөв ба зарцуулалт. Meta Ads-ийн карт слайдын «Meta зар — долоо хоногийн тойм»-той ижил 8 үзүүлэлт, үр дүн төрлөөр, их зардалтай 4 кампанит ажил, дарж нээдэг бүтэн кампанит ажлын хүснэгттэй (доорх «Meta зар»).
- **02·3 «Дэлгэцийн зураг, нэмэлт слайд»**: контент төлөвлөгөөнөөс гадуурх слайд, тухайлбал Page insights, Ads Manager, CallPro, SMS, сэжим хуудас, ManyChat-ийн дэлгэцийн зураг.

Нэмэлт слайд бүр сэдэв, гарчиг, ≤ 9 зураг (20261023152000), тайлбар/дүгнэлт (≤ 2000 тэмдэгт) агуулна. Зургийг сонгох, чирж оруулах, эсвэл дэлгэцийн зургийг **Ctrl+V / ⌘V-ээр шууд буулгаж** оруулна.

## Контент төлөвлөгөө (Контент календарь)

- Өмнө нь `/marketing/calendar` зөвхөн контент үүсгэдэг байсан тул төлвийг өөрчлөх, төлөвлөгөөг гүйцэтгэлтэй харьцуулах боломжгүй байв. Мөр нь ерөнхий `/api/marketing/data` route-оор дурын баганаар бичигддэг байсан.
- Одоо бүх бичилт `/api/marketing/content-plan` (GET ≤ 93 өдөр, POST) болон `/api/marketing/content-plan/[id]` (PATCH, DELETE)-оор явна. Бүгд Zod allow-list-тэй, `marketing-roi` эрхтэй. `content_calendar`-ийг ерөнхий route-оос хассан.
- Контент: гарчиг, төрөл (пост, story, reel, блог, имэйл, зар, эвент), платформ, огноо, төлөв (төлөвлөсөн → хийгдэж байна → бэлэн → нийтэлсэн / цуцалсан), хариуцагч, тайлбар, ≤ 6 постер/reel-ийн зураг (`report-media`, шинэ зураг нь тухайн хэрэглэгчийн upload).
- Засварыг `updated_at`-аар шалгана. Өөрийн үүсгэсэн контентыг бичих эрхээр, бусдынхыг устгах эрхээр устгана. Эрхгүй бол «Цуцалсан» төлөв тавина.
- Календарь дээр контент дарж засна, нийтэлсэнд ✓ тэмдэг гарна, сарын гүйцэтгэл харагдана.
- Гүйцэтгэл (`summarizeContentPlan`): цуцалсан контент төлөвлөгөөнд тооцогдохгүй. Хоцорсон = огноо өнгөрсөн, нийтлээгүй. Хоцорсон контент маркетингийн «Энэ хурлаар шийдэх»-д орно.

## Facebook хуудас (2026-10-13)

Холбогдсон Page-ийн хадгалсан органик үзүүлэлтийг (`social_insights_daily`, cron 6 цаг тутам) хурлын долоо хоногоор харуулна. Дэлгэцийн зураг оруулах шаардлагагүй. `GET /api/dashboard/marketing/social-week?meetingDate=` (`marketing-roi`), `lib/marketing/social-week.ts`.

Давхардалгүй хүрсэн хүнийг өдрөөр нэмж болохгүй тул оруулаагүй. «Товч, холбоос дарсан»-ыг (`page_total_actions`) 2026-10-25-нд хассан: Meta Elysium-ийн бүх 42 өдөрт 0 буцаадаг (хуудас үзсэн нь өдөрт 94–1209) — хадгалсаар байгаа ч харуулахгүй.
- **Өдөр:** Meta-гийн Номхон далайн цагийн өдөр.
- **Харьцуулалт:** бүтэн долоо хоног бол өмнөх долоо хоногтой харьцуулна. Дутуу бол өмнөх долоо хоногийн мөн өдрүүдтэй харьцуулна, учир нь хурлын өглөө Meta-гийн Мягмар гараг дуусаагүй байдаг. Дагагчийг 7 хоногийн өмнөх өдөртэй харьцуулна. Аль нэг тал дутуу бол өөрчлөлт гаргахгүй.

## Meta зар (2026-10-20)

Хуучин гар слайдад Ads Manager-ийн кампанит ажлын хүснэгтийг дэлгэцийн зургаар оруулдаг байв. Одоо маркетингийн файл Meta зарыг Ads Manager-ийн хураангуй шиг харуулна. Эх сурвалж нь зөвхөн хурлын долоо хоногийн `meta_ads` сувгийн тайлан (`GET /api/marketing/channel-reports` → `latest.meta_ads`): Meta API-ийн синк (`origin = 'api'`, cron 6 цаг тутам эсвэл «Meta зардал татах») эсвэл Ads Manager-ийн экспорт файл. Дүрэм `lib/marketing/channel-week.ts`-д, хурлын хуудас ба слайд хоёулаа ашиглана.

- **Тойм:** зарцуулсан дүн, impressions, reach, frequency, link clicks, link CTR, CPM, нэг link click-ийн өртөг. Өмнөх ижил урттай тайлантай харьцуулна. Шошго нь өмнөх тайлангийн жинхэнэ урт: залгаа 7 хоног бол «Өмнөх 7 хоног», хурлын долоо хоногоос урт тайланд (жишээ нь 30 өдрийн экспорт) «Өмнөх 30 хоног», залгаа биш бол «Өмнөх тайлан»; 7 хоногийн залгаа тайлангаас бусад үед харьцуулсан тайлангийн огноо, уртыг доор бичнэ. Аль нэг тайлан өдөр дутуу бол (жишээ нь 6/7) харьцуулахгүй, «Өдөр дутуу тул өмнөх долоо хоногтой харьцуулаагүй» гэж бичнэ. Дэд гарчигт хугацаа, Meta API / экспорт файл, хамарсан өдөр, хурлын долоо хоногоос урт эсвэл зөрүүтэй тайлан эсэх. Картын том тоог өргөнөөр нь (жишээ нь «12,345.67 USD») жижигрүүлж нэг мөрт багтаана.
- **Үр дүн төрлөөр:** төрөл бүрийн тоо, кампанит ажлын зорилгоор хуваарилсан зардал, нэг үр дүнгийн өртөг (хүрсэн хүн бол 1000 хүнд). «—»-ийн шалтгааныг төрлөөр нь бичнэ: хүрсэн хүн — өдрийн reach-ийг нэмэхгүй тул давхардалгүй тоо ирээгүй; бусад төрөл — Meta үр дүнгийн тоо өгөөгүй (жишээ нь IMPRESSIONS зорилго) эсвэл файлд Results багана алга; аль ч үед зардлыг харуулна. Meta API-ийн хүрсэн хүн reach зорилготой хэд хэдэн кампанит ажлынх бол кампанит ажил бүрийн давхардалгүй reach-ийн нийлбэр (`metaReachIsSum`) — кампанит ажил хооронд давхцаж болох тул тоо, өртгийг «≈»-тэй, слайд ба хуудсанд тайлбартай харуулна. Энэ долоо хоногт хүргэлтгүй төрөл 0, «хүргэлтгүй». Төрөлд хуваарилаагүй зардал (нийт − Σ төрлийн зардал), нийт зардал тусдаа мөр. Үр дүнгийн нийлбэр мөр хэзээ ч байхгүй. Баганын гарчиг нь «Нэг үр дүнгийн өртөг» (төрлийн нэр биш).
- **Кампанит ажлаар:** кампанит ажил × үр дүнгийн төрөл, зардлаар буурахаар (нийт зардалгүй — валют холилдсон эсвэл зардлын багана алга — бол өөр валютын дүнг харьцуулахгүйн тулд харагдалтаар): нэр (2 мөрт багтахаар үгийн заагаар тайрна), төрөл («(үр дүн)» дагаваргүй), үр дүн, нэг үр дүнгийн өртөг, зардал, impressions, reach (Meta-гийн давхардалгүй тоо ирсэн мөрт л, мөрүүдийг нэмэхгүй), link clicks. Слайдад мөрийн өндрөөр (≤ 11 мөр) хуваана — урт нэрийн хүснэгт хөлийн мөрөнд хүрэхгүй. Задаргаанд кампанит ажлын ID алга тул ижил нэртэй мөр байвал «N мөр (кампанит ажил × үр дүнгийн төрөл)», үгүй бол «N кампанит ажил».
- **Мөнгө:** зардал зарын дансны валютаар (ихэвчлэн USD). ₮ гэж бичихгүй, төгрөгийн зардал, төсөвт нэмэхгүй. Валют холилдсон файлд нийт ба кампанит ажлын зардлыг харуулахгүй, валют тодорхойгүй бол «Валют тодорхойгүй — төгрөг биш».
- **Тэмдэглэл (notes):** тайлангийн бүх анхааруулга (зорилгоор ойролцоо тооцсон үр дүн, цагийн бүс, reach ирээгүй, валют), эх сурвалж, reach/CPM/CTR-ийн тодорхойлолт.
- Meta-гийн үр дүн (тухайлбал «Лид маягт») нь зарын платформын тоо, CRM-ийн лид, гэрээтэй холбохгүй.
- Хурлын долоо хоногт `meta_ads` тайлан байхгүй бол Meta-гийн слайд нэмэгдэхгүй. «Сувгийн экспорт» слайд дутуу эх үүсвэрийг нэрлэнэ; Facebook хуудас API-аар холбогдсон бол (хуудасны үзүүлэлттэй) дутуу экспортод тооцохгүй, «Facebook хуудас: API-аар (Facebook хуудасны слайд)» гэж бичнэ.
- **Дуусаагүй долоо хоног (2026-10-25):** хурлын өглөө Meta API-ийн тайлан 6/7 өдөртэй байдаг. Өмнөх хурлын долоо хоногийн API тайлан тэр өдрүүдийг хамарсан бол `loadChannelReports` өмнөх долоо хоногийн **мөн өдрүүдийг** хадгалсан ad set × өдрийн мөрөөс (`meta_ad_insights_daily`, одоогийн данс; `metaSameDaysTotals` — `lib/marketing/meta-channel-report.ts`) бодож харьцуулна: зардал, impressions, link click, үр дүн төрлөөр ба CPM, CPC, CTR, нэг үр дүнгийн өртөг. Reach, frequency (мөн reach-ийн үр дүн) харьцуулахгүй. Шошго «Өмнөх 7 хоногийн мөн өдрүүд» (Facebook хуудасны слайдтай ижил), `ChannelReportMatch.sameDays` = харьцуулсан өдрүүд. Файлаар оруулсан тайлантай хэзээ ч холихгүй; өмнөх долоо хоногийн тайланг ижил мөрөөс дахин бодоход зардал, харагдалт таарахгүй бол (данс солигдсон г.м.) өмнөх шигээ «Өдөр дутуу тул харьцуулаагүй».

## Холболт, эх сурвалж, төсөв (2026-10-25)

Эзэмшигч Meta-гийн портфолиод бүрэн эрхтэй болж, Meta-г шууд холбодог тул маркетингийн тайлан бүрэн, үнэн байх ёстой:

- **Холболтын төлөв:** `GET /api/dashboard/marketing/connections` (`withRoute`, `marketing-roi`, идэвхтэй төсөл; `lib/marketing/connections-load.ts`): Facebook хуудас ба Instagram холбогдсон эсэх + `social_insights_sync`, сонгосон зарын данс (ID л), токены эх сурвалж (`metaAdsTokenSource`: System User / хэрэглэгчийн) ба хэрэглэгчийн токен дуусах хоног, `meta_insights_sync`/`meta_spend_sync`-ийн сүүлийн төлөв, алдаа, хамралт, төгрөгийн ханш хадгалсан эсэх (`meta_spend_sync.mnt_per_unit`). Токены утгыг хэзээ ч буцаахгүй. Хуудсанд 02·2-ийн доор нэг мөр, маркетингийн файлд нүүрний дараа «Холболтын төлөв» слайд (`connectionRows`). «Энэ хурлаар шийдэх»-д (`connectionDiscussionItems`): «Meta зарын данс холбогдоогүй» (данс сонгоогүй эсвэл хүчинтэй токен алга), «Meta синк алдаатай: …», «Meta токен N хоногт дуусна» (хэрэглэгчийн токен, ≤ 14 хоног), «Төгрөгийн ханш оруулаагүй».
- **Төсөв:** `GET /api/marketing/budget` нь сар бүрийн `spendStatus` (₮-д орсон бүртгэлтэй эсэх, ханшгүй Meta зардал эх валютаар) буцаана. Слайд, карт (`budgetSpendCell`): бүртгэлгүй → «—» (өмнө «0 ₮»); зөвхөн ханшгүй → «—» + «Ханшгүй 1,234.56 USD (₮-д ороогүй)»; хэсэгчлэн → ₮ + «+ ханшгүй … USD», хувь доод хязгаар «72%+». Ханшгүй дүн ₮-ийн нийтэд хэзээ ч нэмэгдэхгүй. Энэ 7 хоногийн зардал ижил дүрмээр (`spendQuality.current.pendingCurrencies`).
- **Ачаалж чадаагүй эх сурвалж:** `exportWeeklyDeck` төсөв, сувгийн тайлан, Facebook хуудас + Instagram-ийн долоо хоног (`social-week`; `instagramError` → тусдаа `instagram` эх сурвалж), холболтын төлөвийг `settle`-ээр уншина (албаны загвартай ижил). Бүтэлгүйтсэн хэсгийн оронд «… мэдээллийг ачаалж чадсангүй» слайд (шалтгаан тэмдэглэлд), `failedSources` — хуудас амжилтын биш анхааруулгын мэдэгдэл гаргана. Өмнө нь хэсэг чимээгүй алга болдог байв.

## Огноогүй гэрээ (2026-10-13)

## Слайдын дараалал

Борлуулалтын файл:

1. Нүүр, «Энэ хурлаар шийдэх» (зөвхөн борлуулалтын асуудал, маркетингийн бус гишүүдийн саад).
2. Борлуулалтын тойм.
3. Сарын төлөвлөгөө ба гүйцэтгэл. Удирдлагын оруулсан `monthlyPerformance`-ийг бүтэн сарын операцийн тайлангаас уншина. Гүйцэтгэл оруулаагүй бол ERP/CRM-ийн сарын гэрээ, ERP-ийн мөнгөн зөрүүг эх сурвалжтай нь харуулна. Орсон мөнгийг зөвхөн санхүүгийн эрхтэй хүн харна.
4. Энэ долоо хоногийн гэрээ (11 мөр тутамд нэг слайд), сарын гэрээ долоо хоногоор, менежерээр, үлдэгдэл блокоор.
5. Давхрын зураглал (блок бүрт). 21-ээс олон давхартай блокийг тэнцүү хуваана.
6. Лидийн эх сурвалж, хөрвөлт (суваг × лид, шилжсэн, гэрээтэй, өртөг).
7. Борлуулалтын нэмэлт слайдууд, маркетингийн бус гишүүдийн ажлын явц, төгсгөл.

Маркетингийн файл (лид, гэрээ, хөрвөлт огт орохгүй):

1. Нүүр «Маркетингийн алба», «Холболтын төлөв» (Facebook хуудас, Instagram, Meta зарын данс, токен, синк, ханш), «Энэ хурлаар шийдэх» (хоцорсон контент, ханшгүй зардал, холболтын асуудал, маркетингийн гишүүдийн саад).
2. Контент төлөвлөгөө ба гүйцэтгэл: 4 карт, өмнөх 7 хоногийн төлөвлөсөн/нийтэлсэн, төрлөөр хүснэгт.
3. Энэ долоо хоногийн контент (хүснэгт, төлөв өнгөөр).
4. Нийтэлсэн/бэлэн контент бүр постер/reel-ийн зурагтайгаа нэг слайд: төрөл, платформ, огноо, хариуцагч, тайлбар.
5. Facebook хуудас: долоо хоногийн үзүүлэлт, энэ долоо хоногт нийтэлсэн постууд. Page холбогдоогүй бол гарахгүй. Дараа нь Instagram: долоо хоногийн үзүүлэлт, нийтэлсэн media (IG холбогдоогүй бол гарахгүй).
6. Маркетингийн нэмэлт слайдууд (дэлгэцийн зураг).
7. Сувгийн экспорт: Facebook хуудасны файл, CallPro, SMS-ийн карт. Оруулаагүй эх үүсвэрийг нэрлэнэ.
8. Meta зар (тайлантай бол): долоо хоногийн тойм (8 карт), үр дүн төрлөөр, кампанит ажлаар (мөрийн өндрөөр хуудаслана). Дээрх «Meta зар».
9. Төсөв ба зарцуулалт (жилийн, он эхнээс, сарын; энэ 7 хоногийн зардал, дууссан кампанит ажил). Бүртгэлгүй бол «—», ханшгүй Meta зардал эх валютаар тусад нь.
   Аль нэг эх сурвалж (холболт, Facebook хуудас + Instagram-ийн нэг хүсэлт, сувгийн тайлан, төсөв) ачаалагдаагүй бол тэр хэсгийн оронд «ачаалж чадсангүй» слайд. Хүсэлт ирсэн ч Instagram-ийн хэсэг уншигдаагүй бол (`instagramError`) Instagram-ийн оронд тусдаа слайд.
10. Дараагийн 7 хоногийн контент төлөвлөгөө.
11. Маркетингийн гишүүдийн ажлын явц (`author_role = marketing`), төгсгөл.

Хуудастай ижил дүрэм үйлчилнэ. Хоосон дүнг 0 гэж бичихгүй, «—» гэж харуулна. Гэрээний дүн, мөнгөн орлого, бартер, Meta-ийн USD зардлыг холихгүй; Meta зарын слайдад ₮ огт гарахгүй. Эх сурвалж ба хязгаарлалт слайдын тэмдэглэлд (notes) бичигдэнэ. Захиалагчийн нэр зөвхөн `contracts` эрхтэй хүнд харагдана. Ачаалж чадаагүй зургийг алгасаад тэмдэглэлд бичнэ.

## Өгөгдөл ба эрх

- `content_calendar`-д `image_paths text[]` (≤ 6, CHECK) ба `created_by uuid` нэмсэн. Хуучин мөрүүд хоосон/NULL хэвээр.
- Хурлын ажлын шинэчлэл (`/api/dashboard/weekly-updates`) зохиогчийн дүрийг (`author_role`, `user_roles`-оос) буцаана. Маркетинг дүртэй гишүүний шинэчлэл маркетингийн файлд, бусдынх борлуулалтын файлд орно.
- Хүснэгт `weekly_report_slides`: төсөл (shop) × хурлын өдөр (Лхагва, CHECK) × хэсэг (`sales | marketing`). Сэдвийг CHECK хязгаарлана. Мөн гарчиг ≤ 200, тайлбар ≤ 2000, `image_paths` ≤ 9 (анх 6; 20261023152000), `position`, зохиогч. RLS идэвхтэй, зөвхөн service_role. Мөрийг зөвхөн API бичнэ.
- Зураг хувийн `report-media` bucket-д хадгалагдана: ≤ 4 MB, JPEG/PNG, `anon`/`authenticated` хандахгүй (RESTRICTIVE policy). Зам: `<shop_id>/<user_id>/<uuid>.<jpg|png>`. Төрлийг файлын эхний байтаас тогтооно (SVG/HTML-ийг нэр солиод оруулж болохгүй). WEBP, GIF, том дэлгэцийн зургийг хөтөч 2400px хүртэл багасгаж JPEG болгоно. Ингэснээр Vercel-ийн 4.5 MB хязгаараас хэтрэхгүй.
- API (`/api/dashboard/weekly-slides*`):
  - Хэсгийн модуль: борлуулалт = `reports`, маркетинг = `marketing-roi`. Унших нь модулийн эрх, бичих нь `requireModuleWrite`. Shop-ийг `getUserShop()` тогтооно, зохиогчийг профайлаас авна, body-оос авахгүй (Zod strict).
  - Шинэ зураг нь тухайн shop-д энэ хэрэглэгчийн upload хийсэн файл байх ёстой. Засахад өмнөх зургууд хэвээр үлдэнэ.
  - Засварыг `updated_at`-аар шалгана: зэрэг засвар 409 буцаана, өөр хүний зургийг устгахгүй.
  - Өөрийн слайдыг бичих эрхээр, бусдынхыг устгах эрхээр (`requireModuleDelete`) устгана. Маркетинг дүр `can_delete = false` тул зөвхөн өөрийнхөө слайдыг устгана.
  - Зураг татах бүрд нэвтрэлт, shop-ийн гишүүнчлэл, зургийг ашигласан слайдын хэсгийн модулийг шалгана. Контент төлөвлөгөөний зураг = `marketing-roi`. Слайдад хараахан ороогүй зургийг зөвхөн оруулсан хүн харна. `Cache-Control: private, no-store`.
- Слайдаас хасагдсан, өөр слайдад ашиглагдаагүй файлыг storage-оос устгана. Dialog-оо хадгалалгүй хаасан бол upload хийсэн файл үлдэнэ (зөвхөн оруулсан хүн харна). Цэвэрлэх cron хараахан алга.
