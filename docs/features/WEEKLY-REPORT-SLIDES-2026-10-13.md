# Лхагвагийн хурлын слайд (.pptx): борлуулалт, маркетинг тусдаа

Огноо: 2026-10-13 (Улаанбаатар). Салбар: `feat/weekly-report-slides`. Эх сурвалж: эзэмшигчийн илгээсэн хоёр слайд. «Garden-Sales-Report-2026.09.09-09.15.pptx» нь 42 слайдтай борлуулалтын тайлан. «Report-260922.pptx» нь 39 слайдтай маркетингийн тайлан бөгөөд Tower, Garden, Elysium-ийг хамарна.

**Эзэмшигчийн шийдвэр (2026-10-13):** маркетингийн алба зөвхөн контент бүтээж, өөрсдийн тусдаа төлөвлөгөөгөөр ажилладаг. Тиймээс маркетингийг борлуулалтын лид, гэрээгээр хэмжихгүй, хоёр тайлан тусдаа байна. Маркетингийн тайлан нь өөрийн контент төлөвлөгөөний гүйцэтгэлээс бүрдэнэ: төлөвлөсөн, нийтэлсэн, хоцорсон контент, постер, сувгийн үзүүлэлт, төсөв, дараагийн 7 хоногийн төлөвлөгөө. Лидийн эх сурвалж, хөрвөлт нь борлуулалтын хэсэгт орно.

**Төлөв:** branch дээр код, тест бэлэн. Migration `20261013140000_weekly_report_slides.sql`-ийг эзэмшигчийн зөвшөөрлөөр 2026-10-13-нд production өгөгдлийн санд оруулж шалгасан (RLS, эрх, хувийн bucket, RESTRICTIVE policy). Энэ нь одоогийн сайтыг өөрчлөхгүй. Код deploy хийгдээгүй: эзэмшигч эхлээд локалд (localhost:3011) шалгана.

## Яагаад

- Лхагвагийн хурлыг үргэлж слайдаар явуулдаг. Hub-ийн «Хурлын бэлтгэл» хуудаснаас зөвхөн текст хуулах, PDF хэвлэх, бүтэн дэлгэцээр харуулах боломжтой байсан.
- Маркетингийн тайлан бараг бүхэлдээ зурагнаас бүрддэг: FB пост/постер, Page insights, Ads Manager, CallPro, масс SMS, сэжим хуудас (Google Form), ManyChat-ийн дэлгэцийн зураг. Hub-д зураг хадгалах газар байгаагүй. AI-ийн хавсралтын upload нь `ai-assistant` эрх шаарддаг бөгөөд хурлын тайланд холбогддоггүй.
- 2026-10-13-ны байдлаар production-д маркетингийн бүх хүснэгт хоосон байв: сувгийн экспорт, Meta зардал, төсөв, кампанит ажил, хурлын шинэчлэл бүгд 0. Маркетингийн ганц хэрэглэгч сүүлд 2026-07-02-нд нэвтэрсэн.

## Хурлын хуудас

Хуудас хоёр хэсэгтэй, слайд нь хоёр тусдаа файл. Файлыг хөтөч дээр үүсгэдэг (`lib/dashboard/weekly-deck-export.ts`). `pptxgenjs` зөвхөн товч дарахад ачаалагдана, хуудасны эхний bundle-д орохгүй.

- **«Борлуулалтын слайд»** (`reports` эрх): `<Төсөл> - Борлуулалт - Лхагва <огноо>.pptx`.
- **«Маркетингийн слайд»** (`marketing-roi` эрх): `<Төсөл> - Маркетинг - Лхагва <огноо>.pptx`.

Борлуулалтын хэсэг:

- 01 Борлуулалтын тойм, 01·2 Гэрээ, үлдэгдэл, давхрын зураглал.
- **01·3 «Лидийн эх сурвалж, хөрвөлт»** (`marketing-roi` эрхтэй хүнд). Энэ нь өмнө «Маркетингийн үр дүн» хэсэгт байсан лид, шилжилт, гэрээлэлт, сувгийн хүснэгт юм. Лидийн эх сурвалж нь борлуулалтын үзүүлэлт тул энд шилжсэн.
- **01·4 «Борлуулалтын нэмэлт слайд»** (`reports`): өдөрлөгийн зураг, хүлээлцсэн байдал, яригдаж буй гэрээ, энэ сарын ажил.

Маркетингийн хэсэг:

- **02 «Маркетинг — контент төлөвлөгөө ба гүйцэтгэл»**: маркетингийн өөрийн төлөвлөгөө (Контент календарь, `content_calendar`).
  - Тайлант долоо хоногийн төлөвлөсөн, нийтэлсэн (%), хийгдэж буй/бэлэн, хоцорсон контентын тоо, төрлөөр задаргаа.
  - Контентын хүснэгт, төлвийг шууд солих боломжтой.
  - Дараагийн 7 хоногийн төлөвлөгөө, «Контент нэмэх».
- **02·2 «Суваг: Page, Ads, CallPro, SMS · төсөв»**: Facebook хуудасны долоо хоногийн үзүүлэлт (доорх), сувгийн экспорт/Meta API, маркетингийн жилийн төсөв ба зарцуулалт.
- **02·3 «Дэлгэцийн зураг, нэмэлт слайд»**: контент төлөвлөгөөнөөс гадуурх слайд, тухайлбал Page insights, Ads Manager, CallPro, SMS, сэжим хуудас, ManyChat-ийн дэлгэцийн зураг.

Нэмэлт слайд бүр сэдэв, гарчиг, ≤ 6 зураг, тайлбар/дүгнэлт (≤ 2000 тэмдэгт) агуулна. Зургийг сонгох, чирж оруулах, эсвэл дэлгэцийн зургийг **Ctrl+V / ⌘V-ээр шууд буулгаж** оруулна.

## Контент төлөвлөгөө (Контент календарь)

- Өмнө нь `/marketing/calendar` зөвхөн контент үүсгэдэг байсан тул төлвийг өөрчлөх, төлөвлөгөөг гүйцэтгэлтэй харьцуулах боломжгүй байв. Мөр нь ерөнхий `/api/marketing/data` route-оор дурын баганаар бичигддэг байсан.
- Одоо бүх бичилт `/api/marketing/content-plan` (GET ≤ 93 өдөр, POST) болон `/api/marketing/content-plan/[id]` (PATCH, DELETE)-оор явна. Бүгд Zod allow-list-тэй, `marketing-roi` эрхтэй. `content_calendar`-ийг ерөнхий route-оос хассан.
- Контент: гарчиг, төрөл (пост, story, reel, блог, имэйл, зар, эвент), платформ, огноо, төлөв (төлөвлөсөн → хийгдэж байна → бэлэн → нийтэлсэн / цуцалсан), хариуцагч, тайлбар, ≤ 6 постер/reel-ийн зураг (`report-media`, шинэ зураг нь тухайн хэрэглэгчийн upload).
- Засварыг `updated_at`-аар шалгана. Өөрийн үүсгэсэн контентыг бичих эрхээр, бусдынхыг устгах эрхээр устгана. Эрхгүй бол «Цуцалсан» төлөв тавина.
- Календарь дээр контент дарж засна, нийтэлсэнд ✓ тэмдэг гарна, сарын гүйцэтгэл харагдана.
- Гүйцэтгэл (`summarizeContentPlan`): цуцалсан контент төлөвлөгөөнд тооцогдохгүй. Хоцорсон = огноо өнгөрсөн, нийтлээгүй. Хоцорсон контент маркетингийн «Энэ хурлаар шийдэх»-д орно.

## Хурлын бэлтгэл — алхам алхмаар (2026-10-13)

Хуудасны дээд хэсэгт борлуулалт, маркетинг тус бүрийн алхмуудыг дарааллаар нь харуулна (`lib/dashboard/meeting-checklist.ts`, `components/weekly/MeetingChecklist.tsx`). Алхам бүр хуудсанд ачаалсан өгөгдлөөс автоматаар төлвөө авна: бэлэн ✓, дутуу ⚠, хийгээгүй ○, шалгах ◌. Мөн хийх газрын холбоостой. Эцэст нь слайд татах товч байна. Хуудсанд ачаалагдаагүй зүйлийг «бэлэн» гэж таамаглахгүй, тэдгээр нь «шалгах» төлөвтэй үлдэнэ.

- **Борлуулалт:**
  1. ERP-ийн гэрээний экспорт (энэ долоо хоногийнх). Огноогүй гэрээтэй бол «хийгээгүй». ERP-гүй төсөлд «гэрээгээ Hub-д бүртгэх».
  2. Байрны үлдэгдлийн экспорт.
  3. Болсон уулзалт.
  4. Өдрийн тайлан (шалгах).
  5. Эзэнгүй, хэтэрсэн лид.
  6. Сарын төлөвлөгөө.
  7. Менежерүүдийн мэдээ.
  8. Нэмэлт слайд (заавал биш).
- **Маркетинг** (лид, гэрээ огт орохгүй):
  1. Контент төлөвлөгөө.
  2. Төлөв шинэчлэх (хоцорсон).
  3. Постер.
  4. Facebook хуудас ба синк.
  5. Сувгийн экспорт (Meta Ads, CallPro, SMS).
  6. Зардал (шалгах).
  7. Дэлгэцийн зураг (заавал биш).
  8. Дараагийн 7 хоног.
  9. Маркетингийн мэдээ.
- **Явц** нь заавал алхмаас хэд нь бэлэн болсныг харуулна. Борлуулалтын хэсэг `reports`, маркетингийн хэсэг `marketing-roi` эрхтэй хүнд харагдана.

## Facebook хуудас (2026-10-13)

Холбогдсон Page-ийн хадгалсан органик үзүүлэлтийг (`social_insights_daily`, cron 6 цаг тутам) хурлын долоо хоногоор харуулна. Дэлгэцийн зураг оруулах шаардлагагүй. `GET /api/dashboard/marketing/social-week?meetingDate=` (`marketing-roi`), `lib/marketing/social-week.ts`.

- **Метрик:** үзэлт, нийтлэлийн оролцоо, шинэ дагагч, хуудас үзсэн, товч/холбоос дарсан, видео үзэлт нь долоо хоногийн нийлбэр. Дагагч нь сүүлийн өдрийн төлөв. Давхардалгүй хүрсэн хүнийг өдрөөр нэмж болохгүй тул оруулаагүй.
- **Өдөр:** Meta-гийн Номхон далайн цагийн өдөр.
- **Харьцуулалт:** бүтэн долоо хоног бол өмнөх долоо хоногтой харьцуулна. Дутуу бол өмнөх долоо хоногийн мөн өдрүүдтэй харьцуулна, учир нь хурлын өглөө Meta-гийн Мягмар гараг дуусаагүй байдаг. Дагагчийг 7 хоногийн өмнөх өдөртэй харьцуулна. Аль нэг тал дутуу бол өөрчлөлт гаргахгүй.
- **Постууд:** долоо хоногт (Улаанбаатарын өдрөөр) нийтэлсэн постууд үзэлтээр эрэмбэлэгдэнэ. Үзэлт, товшилт, like, сэтгэгдэл, хуваалцсан нь сүүлийн синкийн байдлаарх нийт дүн. Meta постын давхардалгүй хүрэлтийг (`post_total_media_view_unique`) 0 гэж буцаадаг тул ашиглахгүй.
- **Хоосон үед:** Page холбогдоогүй бол слайд гарахгүй, хуудсанд «холбоно» гэсэн холбоос гарна. Meta өгөөгүй метрик «—» буюу «Meta өгөөгүй» гэж харагдана.
- **Instagram:** өдрийн үзүүлэлт хадгалагддаггүй тул одоогоор ороогүй.

## Огноогүй гэрээ (2026-10-13)

Elysium-ийн 77 гэрээ ERP-ийн байрны экспортоос үүссэн тул гэрээ байгуулсан огноогүй. ERP-ийн гэрээний экспорт хараахан ороогүй байна. Өмнө нь хурлын тайлан «0 гэрээ, 0₮, 0%» гэж буруу харуулдаг байв. Одоо `lib/dashboard/contract-dates.ts`-ийн дүрмээр:

- Хугацаанд нэг ч гэрээ олдоогүй бол «—» (тодорхойгүй), зарим нь олдсон бол «N+» гэж харуулна.
- Тайлбарт «Огноогүй N гэрээ · ERP гэрээний экспорт хэрэгтэй» гэж бичнэ.
- Сарын гүйцэтгэлийн хувь «—» болно.
- «Энэ хурлаар шийдэх»-д «Огноогүй N гэрээ» нэмэгдэнэ.
- Хуудас, слайд, текст тайлан, AI бүгд энэ дүрмийг ашиглана.
- `loadWeeklySales` нь ERP-ийн гэрээний экспорт байхгүй үед CRM-ийн огноогүй, цуцлаагүй гэрээг тоолж, `sources.undatedContracts` болгоно. Операцийн тайлан `contracts.undatedCount`-ийг ашиглана.

## Слайдын дараалал

Борлуулалтын файл:

1. Нүүр, «Энэ хурлаар шийдэх» (зөвхөн борлуулалтын асуудал, маркетингийн бус гишүүдийн саад).
2. Борлуулалтын тойм.
3. Сарын төлөвлөгөө ба гүйцэтгэл. Удирдлагын оруулсан `monthlyPerformance`-ийг бүтэн сарын операцийн тайлангаас уншина. Гүйцэтгэл оруулаагүй бол ERP/CRM-ийн сарын гэрээ, ERP-ийн мөнгөн зөрүүг эх сурвалжтай нь харуулна. Орсон мөнгийг зөвхөн санхүүгийн эрхтэй хүн харна.
4. Энэ долоо хоногийн гэрээ (11 мөр тутамд нэг слайд), сарын гэрээ долоо хоногоор, менежерээр, үлдэгдэл блокоор.
5. Давхрын зураглал (блок бүрт). 21-ээс олон давхартай блокийг тэнцүү хуваана.
6. Лидийн эх сурвалж, хөрвөлт (суваг × лид, шилжсэн, гэрээтэй, өртөг).
7. Борлуулалтын нэмэлт слайдууд, маркетингийн бус гишүүдийн ажлын явц, төгсгөл.

Маркетингийн файл (лид, гэрээ, хөрвөлт огт орохгүй):

1. Нүүр «Маркетингийн алба», «Энэ хурлаар шийдэх» (хоцорсон контент, ханшгүй зардал, маркетингийн гишүүдийн саад).
2. Контент төлөвлөгөө ба гүйцэтгэл: 4 карт ба төрлөөр хүснэгт.
3. Энэ долоо хоногийн контент (хүснэгт, төлөв өнгөөр).
4. Нийтэлсэн/бэлэн контент бүр постер/reel-ийн зурагтайгаа нэг слайд: төрөл, платформ, огноо, хариуцагч, тайлбар.
5. Facebook хуудас: долоо хоногийн үзүүлэлт (7 карт), энэ долоо хоногт нийтэлсэн постууд. Page холбогдоогүй бол гарахгүй.
6. Маркетингийн нэмэлт слайдууд (дэлгэцийн зураг).
7. Сувгийн экспорт, Meta API.
8. Төсөв ба зарцуулалт (жилийн, он эхнээс, сарын; энэ 7 хоногийн зардал, дууссан кампанит ажил).
9. Дараагийн 7 хоногийн контент төлөвлөгөө.
10. Маркетингийн гишүүдийн ажлын явц (`author_role = marketing`), төгсгөл.

Хуудастай ижил дүрэм үйлчилнэ. Хоосон дүнг 0 гэж бичихгүй, «—» гэж харуулна. Гэрээний дүн, мөнгөн орлого, бартер, Meta-ийн USD зардлыг холихгүй. Эх сурвалж ба хязгаарлалт слайдын тэмдэглэлд (notes) бичигдэнэ. Захиалагчийн нэр зөвхөн `contracts` эрхтэй хүнд харагдана. Ачаалж чадаагүй зургийг алгасаад тэмдэглэлд бичнэ.

## Өгөгдөл ба эрх

- `content_calendar`-д `image_paths text[]` (≤ 6, CHECK) ба `created_by uuid` нэмсэн. Хуучин мөрүүд хоосон/NULL хэвээр.
- Хурлын ажлын шинэчлэл (`/api/dashboard/weekly-updates`) зохиогчийн дүрийг (`author_role`, `user_roles`-оос) буцаана. Маркетинг дүртэй гишүүний шинэчлэл маркетингийн файлд, бусдынх борлуулалтын файлд орно.
- Хүснэгт `weekly_report_slides`: төсөл (shop) × хурлын өдөр (Лхагва, CHECK) × хэсэг (`sales | marketing`). Сэдвийг CHECK хязгаарлана. Мөн гарчиг ≤ 200, тайлбар ≤ 2000, `image_paths` ≤ 6, `position`, зохиогч. RLS идэвхтэй, зөвхөн service_role. Мөрийг зөвхөн API бичнэ.
- Зураг хувийн `report-media` bucket-д хадгалагдана: ≤ 4 MB, JPEG/PNG, `anon`/`authenticated` хандахгүй (RESTRICTIVE policy). Зам: `<shop_id>/<user_id>/<uuid>.<jpg|png>`. Төрлийг файлын эхний байтаас тогтооно (SVG/HTML-ийг нэр солиод оруулж болохгүй). WEBP, GIF, том дэлгэцийн зургийг хөтөч 2400px хүртэл багасгаж JPEG болгоно. Ингэснээр Vercel-ийн 4.5 MB хязгаараас хэтрэхгүй.
- API (`/api/dashboard/weekly-slides*`):
  - Хэсгийн модуль: борлуулалт = `reports`, маркетинг = `marketing-roi`. Унших нь модулийн эрх, бичих нь `requireModuleWrite`. Shop-ийг `getUserShop()` тогтооно, зохиогчийг профайлаас авна, body-оос авахгүй (Zod strict).
  - Шинэ зураг нь тухайн shop-д энэ хэрэглэгчийн upload хийсэн файл байх ёстой. Засахад өмнөх зургууд хэвээр үлдэнэ.
  - Засварыг `updated_at`-аар шалгана: зэрэг засвар 409 буцаана, өөр хүний зургийг устгахгүй.
  - Өөрийн слайдыг бичих эрхээр, бусдынхыг устгах эрхээр (`requireModuleDelete`) устгана. Маркетинг дүр `can_delete = false` тул зөвхөн өөрийнхөө слайдыг устгана.
  - Зураг татах бүрд нэвтрэлт, shop-ийн гишүүнчлэл, зургийг ашигласан слайдын хэсгийн модулийг шалгана. Контент төлөвлөгөөний зураг = `marketing-roi`. Слайдад хараахан ороогүй зургийг зөвхөн оруулсан хүн харна. `Cache-Control: private, no-store`.
- Слайдаас хасагдсан, өөр слайдад ашиглагдаагүй файлыг storage-оос устгана. Dialog-оо хадгалалгүй хаасан бол upload хийсэн файл үлдэнэ (зөвхөн оруулсан хүн харна). Цэвэрлэх cron хараахан алга.
