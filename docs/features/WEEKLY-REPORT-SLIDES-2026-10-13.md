# Лхагвагийн хурлын слайд (.pptx), постер, дэлгэцийн зураг

Огноо: 2026-10-13 (Улаанбаатар). Салбар: `feat/weekly-report-slides`. Эх сурвалж: эзэмшигчийн илгээсэн хоёр слайд. «Garden-Sales-Report-2026.09.09-09.15.pptx» нь 42 слайдтай борлуулалтын тайлан. «Report-260922.pptx» нь 39 слайдтай маркетингийн тайлан бөгөөд Tower, Garden, Elysium-ийг хамарна.

**Төлөв:** branch дээр код, тест бэлэн. Migration `20261013140000_weekly_report_slides.sql` production-д **ороогүй**. Кодыг deploy хийхээс өмнө migration-ийг хэрэглэнэ. Migration-гүй орчинд слайдын API 503 буцааж «шинэчлэлийг суулгана уу» гэж хэлнэ. Тайлан болон `.pptx` экспорт ажилласаар байна, зөвхөн нэмэлт слайд хоосон харагдана.

## Яагаад

- Лхагвагийн хурлыг үргэлж слайдаар явуулдаг. Hub-ийн «Хурлын бэлтгэл» хуудаснаас зөвхөн текст хуулах, PDF хэвлэх, бүтэн дэлгэцээр харуулах боломжтой байсан.
- Маркетингийн тайлан бараг бүхэлдээ зурагнаас бүрддэг: FB пост/постер, Page insights, Ads Manager, CallPro, масс SMS, сэжим хуудас (Google Form), ManyChat-ийн дэлгэцийн зураг. Hub-д зураг хадгалах газар байгаагүй. AI-ийн хавсралтын upload нь `ai-assistant` эрх шаарддаг бөгөөд хурлын тайланд холбогддоггүй.
- 2026-10-13-ны байдлаар production-д маркетингийн бүх хүснэгт хоосон байв: сувгийн экспорт, Meta зардал, төсөв, кампанит ажил, хурлын шинэчлэл бүгд 0. Маркетингийн ганц хэрэглэгч сүүлд 2026-07-02-нд нэвтэрсэн.

## Хурлын хуудас

- **«Слайд (.pptx)»** товч нь хуудасны ачаалсан, эрхээр шүүгдсэн тайлангуудаас засаж болох PowerPoint файл үүсгэнэ. Файлын нэр: `<Төсөл> - Лхагва <огноо>.pptx`. Үүнийг хөтөч дээр үүсгэдэг (`lib/dashboard/weekly-deck-export.ts`). `pptxgenjs` зөвхөн товч дарахад ачаалагдана, хуудасны эхний bundle-д орохгүй.
- **01·3 «Борлуулалтын нэмэлт слайд»** (`reports` эрх): өдөрлөгийн зураг, хүлээлцсэн байдал, яригдаж буй гэрээ, энэ сарын ажил, бусад.
- **02·2 «Постер, контент, дэлгэцийн зураг»** (`marketing-roi` эрх): Сошиал медиа, Пэйж хандалт, Boost / Meta Ads, CallPro, Масс SMS, Сэжим хуудас, Вэб сайт, Чат/ManyChat, Өдөрлөг, Бусад.
- Слайд бүр сэдэв, гарчиг, ≤ 6 зураг, тайлбар/дүгнэлт (≤ 2000 тэмдэгт) агуулна. Зургийг сонгох, чирж оруулах, эсвэл дэлгэцийн зургийг **Ctrl+V / ⌘V-ээр шууд буулгаж** оруулна. Слайдыг дээш/доош, зургийг өмнө/хойш зөөнө.

## Слайдын дараалал

1. Нүүр: төсөл, тайлант хугацаа, хурлын өдөр, харьцуулах хугацаа.
2. Энэ хурлаар шийдэх: хуудасны хэлэлцэх асуудал (≤ 7).
3. Борлуулалтын тойм: шинэ лид, гэрээ, гэрээний дүн, болсон уулзалт (өмнөхтэй харьцуулсан), уулзалтын төрөл, лидийн ажлын дараалал.
4. Сарын төлөвлөгөө ба гүйцэтгэл. Удирдлагын оруулсан сарын төлөвлөгөө, гүйцэтгэлийг (`monthlyPerformance`) бүтэн сарын операцийн тайлангаас уншина. Гүйцэтгэл оруулаагүй бол ERP/CRM-ийн сарын гэрээ, ERP-ийн мөнгөн зөрүүг эх сурвалжийг нь бичиж харуулна. Орсон мөнгийг зөвхөн санхүүгийн эрхтэй хүн харна.
5. Энэ долоо хоногийн гэрээ: 11 мөр тутамд нэг слайд, сүүлийнх нь нийтийн мөртэй.
6. Сарын гэрээ долоо хоногоор × бүтээгдэхүүнээр.
7. Менежерээр.
8. Үлдэгдэл блокоор.
9. Давхрын зураглал (блок бүрт). 21-ээс олон давхартай блокийг хэд хэдэн слайдад тэнцүү хуваана. Худалдаанд байгаа байрыг цэнхэр, зарагдсаныг менежерийн нэртэй харуулна.
10. Борлуулалтын нэмэлт слайдууд.
11. Маркетингийн үр дүн: жилийн төсөв, он эхнээс болон тухайн сарын зарцуулалт, лидийн хөрвөлт, өртөг.
12. Сувгаар лид, гэрээлэлт, зардал.
13. Сувгийн экспорт, Meta API: Meta Ads, Facebook хуудас, CallPro, SMS-ийн гол үзүүлэлт. Экспорт оруулаагүй сувгийг жагсаана.
14. Маркетингийн нэмэлт слайдууд (постер, дэлгэцийн зураг). Олон зурагтай бол сүлжээгээр байрлуулна. Тайлбар урт бол хажууд нь гарна.
15. Багийн явц: хүн бүрт нэг слайд (хийсэн ажил, саад, дараагийн алхам).
16. Төгсгөл.

Хуудастай ижил дүрэм үйлчилнэ. Хоосон дүнг 0 гэж бичихгүй, «—» гэж харуулна. Гэрээний дүн, мөнгөн орлого, бартер, Meta-ийн USD зардлыг холихгүй. Эх сурвалж ба хязгаарлалт слайдын тэмдэглэлд (notes) бичигдэнэ. Захиалагчийн нэр зөвхөн `contracts` эрхтэй хүнд харагдана. Ачаалж чадаагүй зургийг алгасаад тэмдэглэлд бичнэ.

## Өгөгдөл ба эрх

- Хүснэгт `weekly_report_slides`: төсөл (shop) × хурлын өдөр (Лхагва, CHECK) × хэсэг (`sales | marketing`). Сэдвийг CHECK хязгаарлана. Мөн гарчиг ≤ 200, тайлбар ≤ 2000, `image_paths` ≤ 6, `position`, зохиогч. RLS идэвхтэй, зөвхөн service_role. Мөрийг зөвхөн API бичнэ.
- Зураг хувийн `report-media` bucket-д хадгалагдана: ≤ 4 MB, JPEG/PNG, `anon`/`authenticated` хандахгүй (RESTRICTIVE policy). Зам: `<shop_id>/<user_id>/<uuid>.<jpg|png>`. Төрлийг файлын эхний байтаас тогтооно (SVG/HTML-ийг нэр солиод оруулж болохгүй). WEBP, GIF, том дэлгэцийн зургийг хөтөч 2400px хүртэл багасгаж JPEG болгоно. Ингэснээр Vercel-ийн 4.5 MB хязгаараас хэтрэхгүй.
- API (`/api/dashboard/weekly-slides*`):
  - Хэсгийн модуль: борлуулалт = `reports`, маркетинг = `marketing-roi`. Унших нь модулийн эрх, бичих нь `requireModuleWrite`. Shop-ийг `getUserShop()` тогтооно, зохиогчийг профайлаас авна, body-оос авахгүй (Zod strict).
  - Шинэ зураг нь тухайн shop-д энэ хэрэглэгчийн upload хийсэн файл байх ёстой. Засахад өмнөх зургууд хэвээр үлдэнэ.
  - Засварыг `updated_at`-аар шалгана: зэрэг засвар 409 буцаана, өөр хүний зургийг устгахгүй.
  - Өөрийн слайдыг бичих эрхээр, бусдынхыг устгах эрхээр (`requireModuleDelete`) устгана. Маркетинг дүр `can_delete = false` тул зөвхөн өөрийнхөө слайдыг устгана.
  - Зураг татах бүрд нэвтрэлт, shop-ийн гишүүнчлэл, зургийг ашигласан слайдын хэсгийн модулийг шалгана. Слайдад хараахан ороогүй зургийг зөвхөн оруулсан хүн харна. `Cache-Control: private, no-store`.
- Слайдаас хасагдсан, өөр слайдад ашиглагдаагүй файлыг storage-оос устгана. Dialog-оо хадгалалгүй хаасан бол upload хийсэн файл үлдэнэ (зөвхөн оруулсан хүн харна). Цэвэрлэх cron хараахан алга.
