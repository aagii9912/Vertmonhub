## 1. Шийдвэр: shop = төсөл

Эзэмшигч 2026-10-04-нд баталсан: **төсөл бүр тусдаа shop** (ажлын орчин) бөгөөд төсөл дотор дэд төсөл үүсгэхгүй. Mandala Garden, Mandala 360&365 Tower, Elysium Residence тус бүр өөрийн лид, маркетинг, жилийн маркетингийн төсөв, менежер, тайлантай. Нэг ажилтан олон төсөлд гишүүн байж болно. Header-ийн «Төсөл» цэсээр сольж ажиллана.

- Migration `20261004130000_project_shops.sql`:
  - `create_project_shop` RPC нь shop, түүний ганц төслийн мөр, сонгосон ажилтнуудын гишүүнчлэл, admin audit-ийг нэг гүйлгээнд үүсгэнэ.
  - `projects_one_per_shop` trigger нь төсөлтэй shop-д хоёр дахь төсөл нэмэхийг болон тийш нь төсөл зөөхийг хориглоно.
  - Ганц төсөлтэй shop-ийн нэр төслийн нэрийг дагана.
- Админ → Төслүүд: «Шинэ төсөл» нь шинэ shop үүсгэнэ. Удирдлага, маркетинг анхнаасаа хандана. Хуучин олон төсөлтэй shop-ийг картан дээр анхааруулна.
- Sidebar болон гар утасны толгойд «Төсөл» солих цэс нэмэгдсэн.
- Лид, уулзалт үүсгэхэд төсөл заагаагүй бол shop-ийн ганц төслийг авна. Ганц төсөлтэй орчинд төсөл сонгох талбар, шүүлтүүр нуугдана.
- Маркетингийн төсөв: ганц төсөлтэй орчинд хуудас нь тухайн төслийн **жилийн үндсэн төсөв**. Сараар хуваарилж, зарцуулалттай харьцуулна.

## 4. Лхагва гарагийн тайлан — долоо хоногийн дэг

Тайлант долоо хоног нь өмнөх Лхагва гарагаас Мягмар гараг хүртэл (Улаанбаатарын цагаар). Сарын явцыг долоо хоногоор харуулахдаа долоо хоногийг сарын хилээр тасална. Эхэнд үлдсэн 1 өдрийн хэсгийг дараагийн долоо хоногтой нийлүүлнэ: 9-р сарын 1-р долоо хоног = 09.01–09.08.

Мягмар гарагт:

1. **ERP экспорт (төсөл бүрээр):** «ERP · Долоо хоногийн тайлан» хуудсанд дараах хоёр экспортыг оруулна.
   - Гэрээний экспорт (`property.sale`). ID баганууд: «Гэрээний дугаар» + «Бүтээгдэхүүн». Нэг гэрээнд зогсоол, агуулах хоёулаа байж болдог.
   - Бүтээгдэхүүний экспорт. ID баганууд: «Бүтээгдэхүүний төрөл» + «Загвар» + «Код».
2. **Маркетингийн экспорт:** Meta Ads, Facebook хуудас, CallPro, SMS-ийн экспортыг төсөл бүрээр оруулна (§5).
3. **Ажлын шинэчлэл:** менежер бүр хийсэн ажил, саад, дараагийн алхмаа «Хурлын бэлтгэл»-д бичнэ.

Лхагва гарагт «Хурлын бэлтгэл» хуудсанд төслөө сонгоод «Танилцуулах», «PDF / хэвлэх» эсвэл «Хуулах» үйлдлийг ашиглана.

Борлуулалтын хэсэг (`GET /api/dashboard/reports/weekly-sales`):

- Энэ долоо хоногийн гэрээ: огноо, бүтээгдэхүүн, блок, тоот, захиалагч, м², дүн, урьдчилгаа, төлсөн, менежер, суваг.
- Сарын гэрээ долоо хоног × бүтээгдэхүүнээр, сарын төлөвлөгөөтэй харьцуулна (`team_sales_targets` — төслийн shop-ийн төлөвлөгөө).
- Менежерээр: 7 хоног, сар, мөнгөн орлого.
- Мөнгөн орлого: хоёр ERP snapshot-ын «Нийт төлсөн дүн»-гийн зөрүү. Snapshot-уудын огноог тайланд харуулна. Банкны хуулгатай тулгаагүй.
- Авлага: идэвхтэй гэрээний хоцролт, үлдэгдэл.
- Үлдэгдэл блок × төрлөөр, мөн орон сууцны **давхрын зураглал** (давхар × загвар, худалдсан менежерийн нэртэй). «Хүлээлгэсэн» байр давхрын зураглалд «Зарагдсан»-д (бартер бол «Бартер»-т), блокийн хүснэгтэд өөрийн баганад орно. «Худалдаанд»-д хэзээ ч орохгүй (§8).
- ERP экспорт байхгүй бол CRM-ийн гэрээ, `property_units`-ийг ашиглаж, эх сурвалжийг ил бичнэ.

Захиалагчийн нэрийг зөвхөн `contracts` эрхтэй хэрэглэгч харна. Регистрийн дугаарыг огт гаргахгүй. Хоосон дүнг 0 гэж таамаглахгүй.

## 5. Маркетингийн экспорт

Хуудас: **Маркетинг → Экспорт импорт** (`/marketing/channel-reports`, ⌘K-д мөн байна). Migration `20261004140000`.

1. Эх үүсвэрээ сонгоно: Meta Ads Manager, Facebook хуудас, CallPro дуудлага эсвэл масс SMS.
2. Хугацаа анхдагчаар хамгийн сүүлд дууссан Лхагва–Мягмар долоо хоног байна.
3. `.xlsx`, `.csv` эсвэл `.tsv` файлаа оруулна.
4. Баганын тохирол урьдчилан бөглөгдөнө: тухайн төсөлд өмнө хадгалсан тохирол, эсвэл толгойн нэрийн санал. Шалгаад «Дахин тооцоолох» → «Хадгалах» дарна.
5. Ижил хугацааны тайланг дахин оруулбал хуучныг солино.

Тооцооны дүрэм:

- Багана холбоогүй үзүүлэлтийг «Тооцоогүй» гэж харуулна, 0 гэж бичихгүй.
- Тоо биш нүд мөрийн дугаартай анхааруулга болно.
- Reach, Viewers зэрэг давхардах тоог мөрүүдээр нэмэхгүй. Файлын нийт мөрөөс авна.
- Meta-ийн зардал файлын валютаар (USD) хадгалагдана.
- CallPro-ийн дуудлагын жагсаалтаас алдсан дуудлагыг Улаанбаатарын цагаар гаргана. Утасны дугаар хадгалагдахгүй.

Лхагвагийн тайлангийн маркетингийн хэсэг дараахыг харуулна:

- Жилийн үндсэн төсөв, он эхнээс болон тухайн сарын зарцуулалт.
- Эх үүсвэр бүрийн гол үзүүлэлт, өмнөх ижил урттай тайлантай зөрүү.
- Meta-ийн хамгийн их зардалтай кампанит ажлууд.
- CallPro-д хамгийн их дуудлага алдсан цагууд.
- Экспорт оруулаагүй сувгийн жагсаалт.

Бодит экспортын жишээ файл ирэхэд толгойн нэрсийг тулгах шаардлагатай. Ялангуяа Meta-ийн монгол хэлний толгой, CallPro-ийн төлвийн нэрс, «алдсан хугацаа» нийлбэр эсвэл дундаж эсэх, нэг дуудлага хэд хэдэн бүлэгт орох эсэхийг тодруулна.

## 6. KPI v2

Одоогийн Excel загварын сул тал:

- Гэрээний дүн, урьдчилгаа 0 жинтэй.
- Авлагын төлөвлөгөөг гүйцэтгэлтэй тэнцүүлж бичдэг.
- Идэвхийн гүйцэтгэл бүртгэгддэггүй.
- Онооны 40% нь «Хийгдсэн» гэсэн тэмдэглэгээнд оногддог.

v2 нь эдгээрийг засна:

| Бүлэг | Үзүүлэлт | Жин | Эх сурвалж |
|---|---|---:|---|
| Үр дүн 60% | Гэрээний дүн | 25 | ERP гэрээ (захиалгын огноо), дээд хязгаар 150% |
| | Орсон мөнгө (урьдчилгаа + төлбөр) | 25 | ERP «Нийт төлсөн дүн»-гийн зөрүү, 120% |
| | Хугацаа хэтэрсэн авлага барагдуулалт | 10 | ERP «Төлбөр хоцролт»-ын бууралт, 120% |
| Идэвх 25% | Шинэ харилцагчтай уулзалт | 10 | CRM уулзалт, 120% |
| | Дуудлага, чат | 10 | Гараар / CallPro, 120% |
| | Хугацаандаа холбогдсон лид (%) | 5 | CRM лид, 100% |
| Үнэлгээ 15% | Удирдлагын үнэлгээ (1–5) | 15 | Удирдлага |

- Оноо = жин × min(гүйцэтгэл / төлөвлөгөө, дээд хязгаар).
- Төлөвлөгөөгүй эсвэл мэдээлэлгүй мөрийг 0 гэж тооцохгүй. Нийт оноог тооцогдсон жингээр нормчилж, хамрах хүрээг харуулна.
- Зэрэглэл: Онцгой ≥ 100, Сайн ≥ 85, Хангалттай ≥ 70, Сайжруулах < 70.
- Сарын эхэнд админ «Сарын KPI тайлан» → KPI карт → «Төлөвлөгөө, үнэлгээ» хэсэгт төлөвлөгөөг оруулна. Хүснэгт нь `sales_kpi_months`.
- Менежер зөвхөн өөрийн картыг харна.
- Бүлгийн жин 60/25/15-ийг эзэмшигч 2026-10-05-нд баталсан (§8). Бүлэг доторх үзүүлэлтийн хуваарилалт, дээд хязгаар, зэрэглэлийн босго нь хэрэгжүүлсэн кодын анхдагч утга бөгөөд тусад нь батлагдаагүй.

## 7. Засварласан алдаа

- KPI-ийн гэрээний жагсаалт DATE баганыг UTC instant-тай харьцуулдаг байсан. Үүнээс болж өмнөх сарын 31 орж, сарын сүүлийн өдөр хасагддаг байв.
- `manager_performance`, `manager_monthly_sales` view-үүд цуцлагдсан гэрээг тоолдог байсан (migration `20261004145000`).
- Менежерийн гүйцэтгэлийн он UTC цагаас авагддаг байсан.

## 8. Эзэмшигчийн шийдвэр (2026-10-05) ба нээлттэй асуулт

Шийдвэр:

- **«Хүлээлгэсэн»** (`handed_over`) = зарагдаад худалдан авагчид хүлээлгэн өгсөн байр. Зарагдсанд тооцогдоно: давхрын зураглалд «Зарагдсан»-тай хамт (бартер бол «Бартер»), блокийн хүснэгтэд өөрийн баганатай. «Худалдаанд»-д хэзээ ч орохгүй. Б1 блокийн гар тайланд ийм байрыг худалдаанд тоолсон байсан.
- Худалдаанд байгаа байр = зөвхөн «Худалдаанд» (`available`). «Хадгалсан», «Захиалга үүссэн»-ийн ангиллыг энэ шийдвэр тогтоогоогүй. Давхрын зураглалд «Бусад» хэвээр.
- KPI v2-ийн бүлгийн жин: Үр дүн 60, Идэвх 25, Үнэлгээ 15 — батлагдсан. Бүлэг доторх үзүүлэлтийн хуваарилалт, дээд хязгаар (150/120/100%), зэрэглэлийн босго (100/85/70) хэрэгжүүлсэн хэвээр. Эдгээр нь кодын анхдагч утга бөгөөд тусад нь батлагдаагүй.

Шийдвэрийн дагуух засвар:

- Тоолол бүр (Лхагвагийн тайлан, самбар, `property_block_summary`, AI-ийн нөөцийн тоо) «Хүлээлгэсэн»-ийг аль хэдийн зарагдсанд тоолж байсан. Тест нэмсэн.
- AI-ийн гэрээний үйлдэл нэгжийн одоогийн төлөвийг уншиж, зөвхөн урагш шилжүүлнэ. Гарын үсэг: «Худалдаанд» → «Хадгалсан». Төлбөр: «Худалдаанд»/«Хадгалсан»/«Захиалга үүссэн» → «Зарагдсан». Цуцлалт: «Хадгалсан»/«Захиалга үүссэн» → «Худалдаанд». Зарагдсан, хүлээлгэсэн байрыг цуцлалт өөрчлөхгүй. Карт дээр шалтгааныг товч харуулж, шалгасны дараа нэгжийн төлөвийг тусад нь өөрчлөхийг зөвлөнө. Listing байрыг (`properties`) ч мөн адил: «Зарагдсан», «Түрээслэсэн», «Бартер» байрыг гэрээний үйлдэл буцаахгүй.
- AI-ийн нэгжийн төлөв (`update_unit_status`) ба гэрээний үйлдэл preview-д харуулсан төлөвийг баталгаажуулалт руу дамжуулна. Энэ хооронд төлөв өөрчлөгдсөн бол (жишээ нь зарагдсан) юу ч бичихгүй, «төлөв энэ хооронд өөрчлөгдсөн» гэж буцаана. Нэгж/байрны бичилт бүтэлгүйтвэл гэрээ, лидэд хүрэхгүй.
- Байрны (listing) импорт «Хүлээлгэсэн»-ийг `sold`, «Захиалга үүссэн»-ийг `reserved` болгоно. Мэдэгдэхгүй төлөвтэй мөр алдаатай болно, өмнөх шиг «Чөлөөтэй» болохгүй.
- Нэгжийн импорт Excel экспортын «Захиалсан» төлөвийг `ordered` гэж уншина.

- Elysium-ийн Meta Ads Manager экспорт ирсэн. Meta API-аар татах ажлыг `docs/features/META-INSIGHTS-API-2026-10-05.md`-д хөтөлнө. CallPro, масс SMS-ийн бодит экспортын жишээ файл хүлээгдэж байна.
- Mandala 360&365 Tower-ийн байр, гэрээний экспорт.
