# Elysium, Admin ба маркетингийн жилийн төсөв

Огноо: 2026-10-01, Asia/Ulaanbaatar. Энэ ажлын production шалгалт зөвхөн уншилт байсан. Хэрэглэгчийн эрх, бизнес өгөгдөл, төсөв өөрчлөөгүй.

## Elysium-ийн мэдээлэл яагаад харагдаагүй вэ

Production DB-д `Elysium Residence` идэвхтэй төсөл байна. `Elysium ERP` эх сурвалжтай, `2026-09-26` тайлангийн огноотой, 540 суурь мөрийн snapshot хадгалагдсан. ERP дэлгэц анх `ERP` гэж шүүж, зөвхөн шинэ/өөрчлөгдсөн/алга болсон мөр харуулдаг байсан. Иймээс өөр нэртэй хадгалсан snapshot болон анхны суурь мөрүүд харагдахгүй байв.

Одоо дэлгэц хадгалсан эх сурвалжуудыг уншиж, хамгийн сүүлийн багцыг эхэлж нээнэ. Суурь мөрүүд анхнаасаа харагдана. Багц сонголт, уншилтын алдаа болон дахин оролдох үйлдэлтэй.

CRM төслийн холбоос бол ERP snapshot-аас тусдаа. Одоогийн, устгаагүй бичлэгээр:

| Бичлэг | Elysium-д холбогдсон | Байгууллагын төсөлд оноогоогүй |
| --- | ---: | ---: |
| Лид | 114 | 30 |
| Inventory байр (`property_units`) | 0 | 2,544 |
| Гэрээ | 0 | 1,617 |

Төсөлд оноогоогүй гэрээ/байрыг Elysium-ийнх гэж таамаглан холбогоогүй. Admin → Төслүүд дээр холбоотой тоо, байгууллагын оноогоогүй тоо, ERP-ийн тусдаа холбоос харагдана. Тоо унших алдаа гарвал төсөл хэвээр харагдаж, тоог боломжгүй гэж тэмдэглэнэ.

Нотолгоо: `output/admin-project-audit-2026-10-01/live-read-only.json`. Энэ нь schema болон нийлбэр тоо; үйлчлүүлэгчийн хувийн мэдээлэл агуулаагүй.

## Admin-ийн засвар

- Дүрийн хүснэгтэд `super_admin` мөр байхгүй ч серверийн зөвшөөрдөг fallback сонголт UI-д харагдана. Хэрэглэгч дээр «Super Admin эрх өгөх» сонгож, бүх байгууллагад үйлчлэх эрхийн тайлбарыг шалгаад баталгаажуулна. Одоогийн админы эрх хадгалагдана; өөрийн дүр солих/өөрийгөө устгах хамгаалалт хэвээр.
- Хэрэглэгчдийн байгууллага, эзэмшил, идэвхтэй менежерийн холбоос, email баталгаажсан эсэх, сүүлийн нэвтрэлт харагдана.
- Шинэ `sales_manager` үүсгэх, урих болон дүр оноох API/AI урсгал яг тухайн байгууллагын roster-т акаунтыг холбож идэвхжүүлнэ. Бодит профайлын нэр шаардана; өөр акаунтын нэр эсвэл давхар холбоосыг дарж бичихгүй. Бичилт алдахад өөрийн нэмсэн холбоосыг буцааж, буцаалт бүтэлгүйтвэл `partial_failure` буцаана.
- Нэг байгууллагад нэг акаунтыг олон менежерийн нэртэй холбохыг roster API хориглоно. Хуучин давхар холбоосоос runtime эхний нэрийг дур мэдэн ашиглахгүй.
- Акаунт солигдох үед өмнөх админы эрх/байгууллагыг шууд цэвэрлэнэ. Logout-ын дараах хоцорсон refresh хандалтыг сэргээхгүй. Байгуулгын refresh алдахад амжилттай сонгосон байгууллагыг хоосон гэж дарахгүй.
- Admin audit-ийн DB error хариуг ч бүртгэнэ; logging нь өмнөх шиг best-effort хэвээр.

Менежерийн акаунт/roster холбоос нь төслийн харьяаллыг өөрөө тогтоохгүй. Менежерийн төслийн гишүүнчлэл, зөвхөн өөрт хуваарилсан лид харах шинэ бодлого зэрэг хөгжүүлж буй тусдаа ажлын хүрээнд байна. Түүний API, UI, RPC болон migration-ууд энэ release-д ороогүй.

## Жилийн маркетингийн төсөв

`/marketing/budget` дээр он болон «Байгууллагын нийт төсөв» эсвэл төсөл сонгоно. «Төсөв засах» → жилийн дүн → «12 сард тэнцүү хуваарилах» → сарын дүнг шалгах/өөрчлөх → «Хадгалах».

Бүх 12 сарын төлөвлөгөө нэг bulk upsert-ээр атомик хадгалагдана. Бүхэл төгрөгийн үлдэгдэл эхний саруудад хуваарилагдаж жилийн нийлбэр яг хадгалагдана. Сарын нийлбэр жилийн дүнтэй зөрвөл хадгалахгүй. Алдаа гарвал draft хэвээр үлдэж дахин хадгалж болно. Засаж/хадгалж байх үед он, төсөл солихыг хаана.

Байгууллагын төлөвлөгөө хуучин `marketing_budgets`-т хэвээр хадгалагдана. Төслийн төлөвлөгөө тусдаа `marketing_project_budgets`-т хадгалагдана; байгууллагын нийт төсөвт автоматаар нэмэгдэхгүй. Төслийн зардал нь зөвхөн холбоотой бичлэгээр тооцогдож, оноогоогүй зардлыг тусад нь мэдээлнэ. Гэрээний дүнг мөнгөн орлого гэж нэрлэхгүй. Байгууллагын өмнөх `manager_monthly_sales` тооцооны эх сурвалж хадгалагдана.

Төслийн төсөвт additive `supabase/migrations/20261001120000_marketing_project_budgets.sql` шаардлагатай. Энэ migration нь хуучин төсөв, AI upsert conflict, notes-ийг өөрчлөхгүй; шинэ хүснэгт browser grant-гүй, RLS асаалттай, өөр байгууллагын төсөл хадгалахыг trigger хориглоно. SQL regression PGlite дээр migration давтан ажиллуулах, browser access, scope, атомик бичилт, notes хадгалахыг шалгана.

## Баталгаажуулалт ба release-ийн хил

Өмнөх shared workspace дээр нийт 117 test файл, 1,094 unit тест амжилттай. Release нь `origin/main` (`a12de45`)-аас тусгаарласан checkout-д зөвхөн энэ ажлын өөрчлөлтөөр бэлтгэгдсэн. `npx tsc --noEmit` болон production build амжилттай. `test:rbac` нь тусгаарласан PostgreSQL дээр 19 эрхийн шалгалт давсан. Жилийн төсвийн SQL нь PGlite дээр бодитоор ажиллуулсан migration-тэй шалгагдсан.

Шинэ browser suite `playwright.admin-project-budget.config.ts` нь жинхэнэ Next login/cookie/UI-г тусгаарласан Auth болон business API fixture-тэй шалгана. Desktop/mobile тус бүр ERP багц/суурь, жилийн төсвийн preview/алдаа/retry, Super Admin-ийн explicit confirmation шалгана. Энэ нь production DB write, бодит урилга/email delivery, нэвтэрсэн production E2E-ийн нотолгоо биш.

Өмнөх shared workspace-ийн browser suite-ийн 6 болон ERP suite-ийн нэмэлт 2 desktop/mobile шалгалт бүгд амжилттай. Тусгаарласан release checkout дээр 107 файл, 1,012 unit тест; browser suite-ийн 6 desktop/mobile шалгалт; disposable PostgreSQL-ийн 19 RBAC шалгалт болон production build бүгд амжилттай. Шалгасан үр дүн `output/admin-project-budget-release/`-т хадгалагдсан. Screenshot-ууд `test-results/admin-project-budget/`-т, unit үр дүн `output/admin-project-audit-2026-10-01/unit-results.json`-д хадгалагдана.

Production migration болон authenticated production E2E хийгээгүй. Төслийн төсөв хадгалах нь `20261001120000_marketing_project_budgets.sql`-ийг live орчинд ажиллуулахыг шаарддаг. Зэрэг хөгжүүлж буй project/roster scope нь өөрийн companion код, schema, өгөгдлийн тохиргоотой тусдаа release шаарддаг.

Давтах командууд:

```sh
rtk npm run test
rtk npm run typecheck
rtk npm run test:rbac
rtk npm run build
E2E_BROWSER_CHANNEL=chrome rtk npx playwright test --config=playwright.admin-project-budget.config.ts
```
