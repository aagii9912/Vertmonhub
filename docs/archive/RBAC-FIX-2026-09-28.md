# RBAC засвар — 2026-09-28

**Кодын засвар болон DB migration бэлэн. Production migration хэрэгжээгүй; нэвтэрсэн хэрэглэгчийн production урсгал баталгаажаагүй.**
Өмнөх [аудитын](./RBAC-AUDIT-2026-09-27.md) API, шууд DB хандалт, модулийн эрх, төслийн гишүүнчлэлийн зөрчлийг засав. Release нь `origin/main`-ийн `8512b38` хувилбар дээр тулгуурлана. Meta Ads-ийн тусдаа токен, account scope, бичих эрхийн хамгаалалтыг хадгалсан. Хэрэглэгчийн дүр/эрхийн өгөгдөл өөрчлөхгүй.

## Засвар

- API-ийн унших, бичих, устгах үйлдэл бүр холбогдох модуль болон үйлдлийн эрхийг шалгана. AI тохиргоо, харилцагч, байр/зураг, Inbox, маркетинг, судалгаа, AI ярианы орхигдсон замуудыг хамруулав. `admin` нэр дангаараа тайлангийн динамик эрхийг давж гарахгүй.
- `/api/shop` дээр AI, маркетинг, байгууллагын тохиргооны талбарууд тусдаа эрхтэй. Холимог хүсэлт бүх холбогдох эрхийг шаарддаг; эзэмшигч/төслийг body-оор өөрчлөхгүй. Хариунд эрхгүй модулийн тохиргоо болон хадгалсан access token буцаахгүй.
- Meta OAuth эхлүүлэх, callback, page/account сонгох нь маркетингийн бичих эрх шаарддаг. Холболт өөрчлөх замууд эзэмшигчээс гадна зөвшөөрөгдсөн гишүүний төслийг баталгаажуулдаг.
- AI тохиргооны PATCH нь зөвшөөрсөн талбаруудыг л авна. AI яриа нь тухайн хэрэглэгчийн бөгөөд одоо ч хандах эрхтэй төслийнх байх ёстой. Гишүүнчлэл хасагдсан бол хуучин ярианд хандахгүй.
- Судалгааны staff/offline хариулт, CRM харилцагчийн холбоос, staff notes нь судалгааны бичих эрхтэй. Нийтийн online хариулт идэвхтэй судалгаанд ажиллана. Marketing contract-ийн channel болон survey-ийн customer холбоос өөр төсөлд харьяалагдах боломжгүй.
- Шууд URL-аар эрхгүй хуудас нээхэд хуудасны компонент ажиллахгүй. Маркетингийн нэмэх/устгах товч болон sidebar тоолуур эрхээ дагана. Цонхонд буцаж орох, session token шинэчлэхэд эрх дахин татна; хоцорсон хариу logout эсвэл шинэ эрхийг дарж солихгүй.
- `getAuthUserShop` хуучин helper нь owner + member шалгадаг `getUserShop`-ийг ашигладаг болсон.
- Server эрхийн шалгалт одоогийн DB тохиргоог уншина; DB алдаа эсвэл устсан дүрийн үед статик эрх сэргээхгүй. Live DB-д definition мөргүй `super_admin`-ийн тусгай эрхийг хадгална.

## DB хамгаалалт

Migration: `supabase/migrations/20260928120000_rbac_api_boundary.sql`.

- Business болон RBAC хүснэгтийн browser/anon mutation grant-уудыг хасна. Баталгаажуулсан server API нь `service_role`-оор ажиллана. Хувийн task, preferences, profile-ийн self RLS хадгалагдана; TRUNCATE зэрэг RLS-ийг тойрдог эрхийг бүгдээс хасна.
- Business хүснэгтүүдийн уншилтад **restrictive** module + shop policy нэмнэ. Хуучин өргөн permissive policy шинэ шалгалтыг тойрохгүй. Динамик эрхийг DB-ээс шалгадаг private helper нь live DB-д `roles` мөргүй байгаа `super_admin`-ийг танина.
- Shop-ийн шууд уншилт зөвхөн identity багануудаар хязгаарлагдана. Хадгалсан integration token-ууд browser-оос татагдахгүй.
- `products`, `property-images` bucket-ийн upload/update/delete нь server API-аар дамжина. Нийтийн зургийн URL хэвийн; өөр bucket-ээс app bucket руу шилжүүлж тойрох боломжийг мөн хаана.
- Business rows, role assignments, module grants-д өгөгдлийн өөрчлөлт хийхгүй. Live admin/marketing/sales дүрд шинэ модулийг автоматаар нэмж өгөөгүй.

**Дараалал:** эхлээд companion API/UI кодыг deploy хийнэ; дараа нь migration-ийг transaction дотор хэрэгжүүлж `supabase_migrations.schema_migrations`-д `20260928120000` хувилбарыг бүртгэнэ. Хуучин surveys/marketing channels/contracts API нь user client-ээр бичдэг байсан тул migration-ийг түрүүлж хэрэгжүүлж болохгүй.
