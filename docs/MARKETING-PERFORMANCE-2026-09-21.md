# Маркетингийн самбар ба багийн гүйцэтгэл

`/marketing` нь нэгдсэн самбар, багийн гүйцэтгэл, бүртгэлийн гурван хэсэгтэй.
Хэрэглэгчийн өгсөн Marketing Dashboard болон Manager Dashboard Excel-ийн
үзүүлэлтүүдийг одоогийн кампанит ажил, лид, гэрээ, зардлын бүртгэлээс бодно.

## Ажиллах дараалал

1. Акц / контент нэмэх: төсөл, маркетингийн хариуцагч, суваг, эхлэх огноо,
   төлөвийг бүртгэнэ. Дууссан ажилд бодит дууссан огноо оруулна.
2. Meta кампанит ажлын ID байгаа бол холбоно. Дараа нь тэр ID-тай ирэх лидийн
   төсөл, маркетингийн хариуцагч, суваг автоматаар бөглөгдөнө. Одоо байгаа
   лидүүдийг автоматаар нөхөхгүй, төслийн зөрүүтэй лидийг дарж бичихгүй.
3. Бусад суваг болон хуучин лидийг «Лидийн эх үүсвэр холбох»-оос нэрээр хайж
   акцтай холбоно. Акцгүй үед төсөл, хариуцагч, сувгийг шууд оруулж болно.
4. Борлуулалтын менежерт хуваарилах нь одоо байгаа лидийн урсгалаар хийгдэнэ.
   Шинэ хуваарилалтын анхны огноог DB trigger бүх бичих урсгалд хадгална.
   Хуучин хуваарилсан лидийн огноо тодорхойгүй бол өнөөдрийн баталгаажуулалт
   хийж болно. Үүнийг түүхэн шилжүүлсэн өдөр гэж тайлбарлахгүй.
5. Багийн хэсэгт менежер–төсөл–сарын Lead, Deal зорилт, төсөв тохируулна.
   Төсөв бүхэл төгрөгөөр оруулна, самбарт сая төгрөгөөр харагдана.
6. Зардал бүртгэхдээ акц сонгоно. Төсөл, хариуцагч, суваг нь акцаас хадгалагдана.
   Гар зардлыг `marketing_spend_entries`-д хадгална. Meta өдрийн автомат
   зардлыг ижил тайланд нэгтгэнэ; [синкийн дүрэм](./META-DAILY-SPEND-2026-09-21.md).
   Meta snapshot зардлыг давхар нэмэхгүй.
7. Хугацаа, төсөл сонгон тайлан харах, Excel татах, AI дүгнэлт ажиллуулна.

## Тооцооны дүрэм

- Lead: сонгосон хугацаанд Улаанбаатарын цагаар үүссэн, устгаагүй лидийн бүлэг.
- Sales: тэр бүлгийн хугацааны эцэс хүртэл анхны хуваарилсан огноотой лид.
  Зөвхөн менежерийн нэртэй, шилжүүлсэн огноогүй хуучин лидийг таамгаар тоолохгүй.
- Deal: тэр бүлгийн хугацааны эцэс хүртэл хүчинтэй гэрээтэй давхардалгүй лид.
  `hasRealContractFields` дүрэм: дугаартай, эерэг дүнтэй, active/closed гэрээ.
  Нэг лид хоёр гэрээтэй бол Deal нэг. Гэрээний мөнгөн дүнг орлого болгон харуулахгүй.
- Акц/контент: completed төлөвтэй, дууссан огноо нь хугацаанд багтсан ажил.
  Сошиал пост/календарын мөр бүрийг автоматаар акц гэж давхар тоолохгүй.
- Контент: дээрх ажлуудаас content төрөлтэй хэсэг; нийт акц/контентын дотор орно.
- Төлөвлөгөөний хувь: хугацаанд эхлэх, цуцлагдаагүй ажлаас хугацааны эцэст
  дууссан ажлын хувь. Төлөвлөсөн ажилгүй бол хувь тодорхойгүй.
- Өмнөх хугацаа: бүтэн календарь сар бол өмнөх календарь сар; бусад үед ижил
  урттай өмнөх өдрүүд. Өмнөх тоо 0 бол өсөлтийн хувийг таамаглахгүй.
- Сарын зорилт бүтэн нэг сар сонгосон үед бодогдоно. Зорилтгүй/0 хуваарьтай
  үзүүлэлтэд `—` харуулна. Багийн бүх мөрийн зорилт бүрэн үед нийт зорилт бодно.
- Байгууллагын сарын нийт төсөв болон менежер–төслийн төсөв тусдаа төлөвлөгөө.
  Нэгийг нөгөөгөөр автоматаар дарж бичихгүй; бодит зардал нэг эх сурвалжтай.
- Лид ба гар зардлын хариуцагч, сувгийг холбоход хадгална. Акцын эзнийг дараа
  солиход эдгээр түүхэн холбоос өөрчлөгдөхгүй. Автомат Meta зардал нь
  тайлан унших үеийн campaign ID холбоосоор төсөл, хариуцагчид хуваарилагдана.
- Цуцлалт, устгалын өнөөгийн төлөвөөр тайлан дахин бодогдоно; immutable сарын
  тайлангийн архив биш. Өнөөдөр бүрэн дуусаагүй сарыг өмнөх бүтэн сартай харьцуулсан
  хувийг бүтэн сарын гүйцэтгэл гэж тайлбарлаж болохгүй.

## Нэвтрүүлэлт

Эхлээд `20260921120000_marketing_performance.sql` additive migration-ийг суулгана.
Миграцийн хувилбарыг `supabase_migrations.schema_migrations`-д бүртгэх нь төслийн дүрэм.
Дараа нь аппыг байршуулна. Энэ өөрчлөлтөөр production migration/deploy хийгээгүй.
Шинэ хүснэгт/багана байхгүй үед нэгдсэн тайлан 503 буцаана, хоосон тоо гэж үзүүлэхгүй.
Хуучин кампанит ажилд дууссан огноо, төсөл, хариуцагч дутуу бол «Бүртгэл»-ээс нөхнө.
Жишээ Excel-ийн ажилтны нэр, төсөв, тоонуудыг production-д seed хийгээгүй.

## Эрх ба баталгаажуулалт

- Тайлан/экспорт/AI: `marketing-roi`; бичих: мөн модуль + canWrite.
- Лидийн холбоос/шилжүүлэлтийг засахад нэмээд `leads` бичих эрх шаардлагатай.
- API нь баталгаажсан shop-оор шүүнэ. DB trigger гадаад байгууллагын төсөл,
  акцтай холбоос болон холбоостой акцын төсөл солихыг хориглоно.
- Шинэ `marketing_targets` хүснэгт RLS-тэй, browser-ийн шууд унших/бичих эрхгүй.
- UI, экспорт, AI нь `loadMarketingPerformance` / `buildMarketingPerformance` ашиглана.
  Уншилт хуудасладаг; аль нэг эх үүсвэрийн алдаанд тайлан бүхэлдээ алдаа харуулна.

Шалгах командууд:

```sh
npm run typecheck
npx vitest run src/lib/marketing/__tests__ src/lib/ai/orchestrator/__tests__/orchestrator.test.tsx
node scripts/test-marketing-performance.mjs
E2E_BROWSER_CHANNEL=chrome npx playwright test --config=playwright.marketing.config.ts
NEXT_BUILD_DIR=.next-marketing-check npm run build
```

SQL шалгалт disposable PGlite дээр ажиллана. Browser шалгалт тусгаарласан auth,
fixture API ашиглана; production хэрэглэгч, өгөгдөл, Meta эсвэл GPT холболтын баталгаа биш.
