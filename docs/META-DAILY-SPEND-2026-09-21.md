# Meta өдрийн автомат зардал

## Хэрэглэх

`/marketing` → **Meta автомат зардал**. `/dashboard/marketing-roi` дээр сонгосон
зарын данс, байгууллагын хадгалсан USER токеныг ашиглана. Page токеноор орлуулахгүй.

- Cron `/api/cron/ads-insights-sync` нь байгаа 6 цагийн хуваариар сүүлийн 35 өдрийг
  татна. «Meta зардал татах» нь самбарын сонгосон хугацааг, нэг удаад 93 хүртэл
  өдрөөр нөхөж татна. Өнөөдрөөс хойших хугацааг дансны өнөөдрөөр хязгаарлана.
- Өдөр, campaign, account тус бүрээр эх валютын дүнг хадгална. Meta дансны цагийн
  бүсийг харуулна. Улаанбаатарын лидийн огноотой адил цагийн бүс гэж таамаглахгүй.
- MNT дансанд ханш 1. Бусад валютын ханшийг таамаглахгүй: эхлээд синк хийж,
  дансны валютыг уншуулсны дараа байгууллагын **тооцооны ханш** оруулна.
  «Ханшаар дахин тооцож татах» нь зөвхөн сонгосон хугацаанд ханшийг сольж, энэ
  ханшийг дараагийн шинэ мөрүүдийн анхдагч болгоно. Энгийн автомат синк өмнө
  хадгалсан өдрийн ханшийг өөрчлөхгүй. Энэ нь банкны бодит төлбөрийн ханш биш.
- Ханшгүй зардал эх валютаар харагдана; төгрөгийн нийлбэрт орохгүй. Самбар,
  AI, Excel нь бүрэн бус дүнгийн анхааруулгатай.
- Campaign ID-г акцын `external_campaign_id`-тай холбоход төсөл, хариуцагчид
  хуваарилна. Автомат зардал тайлан унших үеийн холбоосыг ашигладаг тул хуучин
  синк хийсэн зардлыг дараа нь холбоход мөн засагдана. Гар зардал, лидийн
  түүхэн холбоосыг өөрчлөхгүй.

## Давхардлыг тооцох дүрэм

Тухайн shop-ийн **амжилттай бүрэн татсан өдрүүдэд** гар `meta_ads`,
`facebook_ads`, `instagram_ads` мөрүүдийг нийтээс хасна; устгахгүй, бүртгэлд
шалтгаантай нь харуулна. Зардалгүй гэж батлагдсан өдөр мөн үүнд орно.
Автомат данс тухайн байгууллагын Meta медиа зардлын эх сурвалж болно.
Бусад зарын дансны гар Meta зардал байгаа бол энэ дүрэм тэдгээрийг мөн
хасах тул тулгаж шалгах шаардлагатай. Контент/үйлчилгээний нэмэлт төлбөрийг
тусдаа тохирох сувгаар бүртгэнэ. Синк хийгээгүй өдрийн гар зардал хэвээр.

`loadMarketingSpend`-ийг маркетингийн самбар, төсвийн самбар, AI төсөв ашиглана.
Excel ба AI гүйцэтгэл ижил performance loader ашиглана. Хуучин 30 хоногийн
`ad_campaigns.spend` snapshot нийт дээр нэмэгдэхгүй; хуучин ROI-ийн snapshot
синк тусдаа хэвээр ажиллана.

## Найдвартай хадгалалт

- Meta Insights `level=campaign`, `time_increment=1`, explicit `time_range`,
  бүх хуудсыг cursor-аар татна. Pagination URL-г шууд дагахгүй.
- Валют, account, огноо, давхардал, дүнг шалгаж дууссаны дараа нэг SQL RPC-аар
  бүх хугацааг transaction дотор шинэчилнэ. Таталт тасарсан/алдаатай бол
  өмнөх ledger өөрчлөгдөхгүй. Хэсэгчилсэн API/DB алдааг success болгохгүй.
- Shop/account/campaign/day unique түлхүүр; дахин синк хийхэд дүн давхардахгүй.
  Meta засварласан/арилсан мөрийг тухайн account, хугацаанд шинэчилнэ.
- Сүүлд эхэлсэн синк хадгалагдсан бол хуучин хариу түүнийг дарж бичихгүй.
- Бүх уншилт shop-scoped; шинэ хүснэгтүүд RLS-тэй, authenticated/anon DML/RPC
  эрхгүй. POST marketing-roi write; GET marketing-roi read; cron CRON_SECRET.
- Token/URL/upstream body-г шинэ синкийн алдаанд харуулахгүй. Одоо байгаа token
  encryption тохиргоог өөрчлөөгүй.

## Суулгалтын дараалал

1. `20260921120000_marketing_performance.sql` болон
   `20260921140000_meta_daily_spend.sql` миграцийг суулгана.
2. Аппын энэ хувилбарыг deploy хийнэ. Хуучин encryption secret-ийг хадгална.
3. Meta USER token нь сонгосон account-д `ads_read` эрхтэй эсэхийг шалгана.
4. Эхний синк, шаардлагатай ханш, campaign→project холбоосыг тохируулна.
5. Нэг өдрийн account/campaign нийлбэрийг Ads Manager-ийн ижил цагийн бүс,
   валютаар тулгана. Cron лог, last_success_at дараагийн удаа шинэчлэгдэхийг шалгана.

Энэ ажлын хүрээнд production миграци/deploy хийгдээгүй; жинхэнэ Meta account-аас
зардал татагдсан гэж батлаагүй. Browser fixture нь локал интерфейсийн шалгалт.

## Шалгах команд

```sh
npx vitest run src/lib/marketing/__tests__
node scripts/test-meta-spend.mjs
E2E_BROWSER_CHANNEL=chrome npx playwright test --config=playwright.marketing.config.ts
npm run typecheck
```

Meta-ийн өөрийн [Marketing API collection](https://www.postman.com/meta/facebook-marketing-api/documentation/0zr4mes/facebook-marketing-api-mapi)
дахь `time_increment`, `time_range`, `account_currency` параметрүүдийг ашиглав.

## Локал шалгалтын үр дүн

- Холбогдох маркетинг, санхүүгийн integrity, AI orchestrator: **93/93**.
- SQL: давтан migration/import, atomic rollback, rate history, zero-day coverage,
  account/shop isolation, stale write rejection, RLS/RPC эрхийн шалгалт тэнцсэн.
- Playwright: desktop/mobile-ийн **4/4** урсгал; FX болон failed-sync үед
  хадгалсан дүнг хэвээр харуулахыг шалгасан. Скриншотуудыг нягталсан.
- TypeScript, өөрчилсөн хэсгийн ESLint, production build тэнцсэн.
- Нийт Vitest: **634 тэнцсэн, 1 унасан**. Өмнө нь өөрчлөгдсөн Button-ийн lg
  хэмжээ 44px боловч `src/components/__tests__/Button.test.tsx:82` нь 40px
  хүлээдэг. Энэ ажил Button-ийн код/тестийг өөрчлөөгүй.
